## 术语与回退分支

| 名称 | 含义 |
|---|---|
| T0 | 源停写/停机后的已验证、受保护恢复点 |
| T1 | 目标首次启动后可能产生新数据时，停写取得的最新已验证、受保护恢复点 |
| R0 | 首次启动前恢复原源盘/注册；首启后的例外需完整证据和明确接受验证副作用丢弃 |
| R1 | 按T1最新数据恢复，不能直接启动旧源数据 |
| A/B/C | A=累计认领后有空间放T1副本；B=明确批准释放精确旧源卷后恢复T1；C=保全可读盘/恢复点并等待修复或另批恢复位置 |
| 栅栏/退注册 | 栅栏阻止生产网络和并发写入；退注册仅移除配置，保留真实源盘 |
| 权威谱系 | 目标首次启动后唯一被允许继续使用的数据版本；无法证明目标未启动时按T1处理 |

## 技术取舍

| 路径 | 结论 | 依据/代价 |
|---|---|---|
| 直接离线qm/pct migrate并映射LVM到ZFS | 不采用 | 本机raw+size与zfs流无共同格式；原计划的简单命令不成立 |
| 热迁移 | 不采用 | host CPU型号不同，Cloud-Init/TPM可能仍走离线传输；不符合既定冷切换 |
| 目录存储过渡后再移动磁盘 | 不作默认 | 增加临时存储及第二次复制；fileserver（900GiB）的容量峰值和回退都会更复杂 |
| 原生destroy源guest后同ID恢复 | 不采用 | 会删除源盘、ACL/firewall，回退只剩备份；不是本轮保留原盘的目标 |
| 冷备份恢复＋仅退源注册 | 主方案（[ASSUMPTION]：须先通过内部API演练并获批准） | 无块格式互导、可文件级恢复800GiB、原盘可回退；需要内部API演练和严格串行身份交接 |

这里的“迁移完成”包括业务数据、配置和管理身份，不只是目标显示running。同ID恢复之前必须先退原注册；不得对仍注册在pve1的ID使用force覆盖。备份恢复不把原LVM快照链搬过去；本次已删Windows快照，实施前还需检查新快照并另行决定保留策略。

## 故障域、管理与恢复点

PBS不是独立物理服务器：仓库pbs.tf声明它为pve2上的VM100、16GiB内存、HBA/SSD直通。ARCHITECTURE-SPINE.md的拓扑图按该既有声明修正，实施前复核；不能仅由pve2与PBS两项连接检查失败推断相同故障原因。VM108验收开机与PBS verify/恢复会共用pve2的CPU、内存及I/O。禁止在这次adoption中更改PBS任何agent/boot/keyboard/hostpci字段或触发重启，bpg 0.70.0的相关已知问题是明确边界。

T0/T1由本次操作者保护和保留：创建时设置protected并在验证后复核，任何新作业retention均不能解除；pve2 VM108的后续备份使用专用namespace，原集群namespace不整体改动。PBS的protected防误prune，但不会在另一个故障域产生副本。用户已接受沿用该共享故障域；pve2失效可能使VM108最新状态和PBS同时不可读。只按实际可达且验证通过的恢复点恢复，登记其数据截止点并明确较新数据可能不可恢复，不声称RPO0或双机故障回退保证。

VM108目标首次启动前也需按已演练流程退下pve0源注册、保留原盘并留置ID108；这比仅onboot=0更强。目标首次启动后是唯一权威谱系，不能因它当前关机就重新启动旧源。

回退按node/pool累计认领，不按guest各算一遍同一空闲空间；A分支必须对全体已首次启动目标的来宾合计成立，B分支依赖事先明确的精确源卷释放授权，C表示保全目标修复而非保证回源。临时试恢复VMID占用也计入本次账本，不从128GiB余量中无记录借用。

三项用户选择已明确，见“方案状态与实施准入”；现场准入不满足时不放行相关阶段。

## 字节容量账本

下列来自本轮只读核查；不预支压缩/去重收益，不把单盘1TB称1TiB。

| 项目 | 当前字节 | GiB约值 | 处理 |
|---|---:|---:|---|
| vmdata available | 722047012864 | 672.46 | 目标新增预算336GiB，保留余量128GiB |
| rpool/data available | 942772604928 | 878.02 | CT111数据quota上限800GiB；系统可写余量运行下限64GiB（非硬预留） |
| CT111 ext4 Used | 730980683776 | 680.78 | 是源文件系统已用，不能直接作ZFS恢复精确大小 |
| CT111 apparent du | 730989341115 | 680.79 | lost+found报权限错误，该du值仅为下界，需在宿主补审 |
| VM108源zvol used | 109055836160 | 101.57 | 源保留时不释放 |
| 其中usedbyrefreservation | 93271642112 | 86.87 | 不可把逻辑100GiB全算作即时物理释放 |

目标VM主盘284GiB；CT根盘32GiB；加入zvol预留、EFI/TPM/Cloud-Init和舍入后采用336GiB准入预算。**即便VM108源盘暂不删除，672.46−336≈336.46GiB，仍大于128GiB余量。** 原“释放VM108源盘后剩约450GiB”不作为准入条件。

CT111目标为ZFS subvolume，不是900GiB raw zvol。命令中的ZFS/PVE容量后缀G按GiB核对，Samba值也须按部署版本确认二进制单位后再比较；单位未核实不得以800字符串认定相等。创建时refquota=800GiB，恢复后、开放生产写入前核实quota=800GiB限制含快照的合计占用；必须设置reservation=800GiB以保护配额空间，设置失败即停止。878.02−800≈78.02GiB，较64GiB系统底线只有约14GiB弹性：任何新系统快照/增长都要重算。若因容量、元数据或配额语义不能满足则停止，不能降低系统底线或提高800GiB限额。

64GiB是运营准入/停止线，CT111 reservation不为兄弟dataset或系统硬性保留64GiB，暂停Time Machine本身也不会释放这份reservation。账本须列出rpool所有dataset、祖先限制、实际PVE系统dataset available与非CT111增长；目标写入开启前和观察期间复查，预测新增写入会使系统可写余量低于64GiB则不开始；余量到达64GiB时暂停Time Machine和其他获准的非系统新增写入并处理容量，不能提高quota或删除未获准数据。若需要硬保证，须另行设计系统dataset预留策略并修订本方案。

两台源Mac的512GB和256GB是源盘容量说明，不是历史备份硬上限；768十进制GB约715.3GiB，不能按768GiB算。迁前Samba向客户端报告800G；迁后报告值改为760GiB（确认部署版本G为二进制单位后设置760G，即816043786240字节），相对800GiB硬限额留40GiB（42949672960字节）。报告值不等于文件系统硬限额；两Mac共享同一个800GiB文件系统上限。Samba配置沿用Webmin/操作者的既有ownership。仓库configure-fileserver-timemachine.yml是一次性bootstrap且默认1T，迁移期间禁止重跑；不擅自改为Ansible常规接管。PVE mp0 size须等于refquota，Terraform adoption声明同值，quota/reservation由变更清单统一管理，禁止任一方单独扩容。

源和目标文件系统元数据占用不同，最终以完整清单及目标实际used/available验收。

PBS须承载原有数据、每guest T0及故障时T1。所有待迁来宾的逻辑盘容量合计约1316GiB（含VM108及CT111原900GiB）；按T0、T1两轮且不计去重，恢复点预算约2632GiB，另加元数据和保留余量。既有PBS空闲数字已过时，不宣称满足。禁止将681GiB tar或suspend临时副本放到pve0系统盘；不新增本地备份fallback。

## 数据与切换协议

1. 记录每guest的业务停止/恢复方法、完整磁盘/挂载、权限/firewall及管理绑定；明确后台任务、Webhooks、定时器、两Mac备份与HA自动化。

3. PBS恢复点成功、保护与验证通过后，源仍注册时采集宿主离线完整清单并正常卸载；之后只退源注册，保留原盘。在原生配置锁保护下归档并移除源配置；确认集群中ID无冲突后，恢复同ID目标。
4. 目标先停止/onboot=0；所有rootfs/mp显式映射。CT111按文件恢复到新800GiB subvolume；源ext4不缩、不修改900GiB声明。
5. 先离线比对内容和元数据，再隔离启动验证。数据库自启动可能产生新写入：即使未开放客户端也要记录；此后按T1路径判断，不把“无客户端”误作“无目标写入”。
6. 迁后管理对齐后开放生产入口，记录时间与唯一写入者；任何失败先停写、保全最新数据，再选择R0或R1回退路径。
