# 数据验证与回退操作


用于runbook的TARGET_RESTORED后验证和任何失败时的回退决策。T0须已验证并protected；清单工具见runbook附录B，栅栏见附录C。按下文选择R0/R1，不能仅凭目标当前关机推定无新数据。

## 完整性证据

每个恢复点对应一个数据截止点。清单生成/比对按runbook附录B，网络栅栏按附录C；两份工具均为需审阅/演练的文档内草稿。VM必须完整备份所有业务磁盘/EFI/TPM，并验证文件系统、关键数据库/应用和外部依赖；备份chunk校验不等于应用恢复验证。原地系统日志/数据库启动会写新数据，需区分可忽略启动元数据与业务变化，不能把“无客户端”当作严格无新写入。

CT111和CT118的数据校验在源停写与目标未开放写入的视图下进行，口径如下：

| 项目 | 通过条件 |
|---|---|
| 路径/类型 | 完整相对路径集合相同；包含隐藏文件、符号链接、空目录；路径使用NUL/等价无歧义编码 |
| 内容 | 所有普通文件字节数及SHA256相同，不只抽样；稀疏文件按逻辑字节摘要 |
| 身份/权限 | mode、数值UID/GID、ACL、xattr逐项比对，宿主视图用相同ID偏移；Samba streams_xattr不能遗漏 |
| 链接 | 符号链接目标、硬链接组关系一致；不比较不同文件系统的inode数字 |
| 时间/稀疏 | mtime按来源分辨率对比；ctime/inode/物理块数不要求相同；不把物理块数变化误判数据丢失 |
| 容量 | ZFS总quota/refquota/预留及源/目标used/available账本通过，无ENOSPC/权限/读取错误 |
| 业务 | 两Mac识别原历史、分别完成增量备份和代表性文件恢复；Hindsight查询/客户端、FunASR识别、HA集成等通过 |

完整清单由runbook附录B脚本经审阅/演练后生成，必须检查退出码并原样保存错误；工具缺失不安装，改为阻塞。不要使用忽略error的find/xargs管道或只比较最终sha256的空输出。lost+found若不可读，须在源停机后由宿主离线核实内容并记录处理：空系统目录可作为明确排除项，存在业务文件则补采/恢复；不自动假定它为空。

目标数据集先完整比对再启动SMB。若要在容器内核对而必须启动，先封闭生产网络且屏蔽SMB、数据库等写入服务，避免清单基线被自身启动修改；具体屏蔽须记录并在切换时恢复。完整校验数百GiB本身耗时，计入窗口。

## 回退容量认领

沿用同一私有变更清单的容量部分，不新建另一套业务状态数据库。键为node/pool；每行含guest、数据截止点、A/B/C、最高恢复写入字节、该池认领额、metadata需求、已认领合计、剩余与原卷释放前提。对pve0整机故障计算全体已首次启动目标的guest的合计，而非只证明某一个能回退。

建议下限（实施前须确认）：nvme-lvm data保留max(32GiB,池大小5%)；local-lvm data保留max(16GiB,池大小5%)；metadata至少保留20%空闲，任何预估恢复会越线则不认领A。当前nvme-lvm已用约93%，这些阈值不是“它已健康宽裕”的结论。对无法从实际T1估计metadata新增量的池不认领A，先保全/修复或选定批准B/C。读取日志中data/metadata报错即停止，不以thin逻辑900GiB当作可写字节。

A分支必须在扣除原卷、已认领恢复、临时试恢复及安全余量后仍有空间；B分支的旧源卷释放也按池合计重算，不能承诺所有回退都能同时完成。C在目标主机失效时表示保全可读的目标盘/PBS并等待修复或另行批准的恢复位置，不等于目标仍能运行。VM108 R1回pve0时保留旧100G卷与新增恢复写入都计入vmdata；禁止rescan把旧盘重新挂入权威guest。

## 通用回退条件

- 按runbook附录F累计认领node/pool空间；同一份free不能被多个guest重复分配。更新认领后才允许目标首次启动，整机故障的全体A/B/C必须显式签入变更单。
- T0/T1验证后立即protected并登记完整PBS身份；迁后作业retention不能解除保护。pve2 VM108新备份独立namespace，读原T0用其原namespace的alias。
- PBS实际位于pve2 VM100（以仓库现有声明规划，实施前复核）；若pve2故障，VM108最新运行状态和备份服务可能同时不可达。用户已接受该现状，不保证双机故障回退。此时先核实恢复点能否读取，登记server/datastore/namespace/type/ID/timestamp和最后业务数据截止点；只能承诺恢复到实际可读且验证通过的点，晚于该点的数据不保证保留。没有可读恢复点时保全可读磁盘并等待修复，不启动旧盘冒称最新状态。
- 所有恢复后的QEMU VM先统一设为onboot=0，再检查磁盘、网络、ACL和唯一权威谱系。涉及保留的同ID旧盘时禁止rescan，也禁止自动ID复用。
- VM大盘可按源盘长度计算原始块摘要，作为额外强证据；只在两侧停止、尚未修改数据/首次启动时比较实际同一业务盘/EFI/TPM。Cloud-Init重建盘或经显式转换的盘不要求字节相等，但须记录原因。耗时计入窗口，源/目标实际size与完整volid先核实。


运行和耐久性准入：已选择按实测受控超配及接受共享故障域；runbook附录G的启动/停止线、值守采样和已批准停止范围必须落实后才放行。CT111报告760GiB、硬限额800GiB及40GiB差额须核验。CT111新备份用stop而非snapshot，protected恢复点verify通过；原盘清理仍需另行授权且须有迁后数据盘备份。rpool SMART及历史错误解释不能用ONLINE一词替代。网络栅栏须在演练中验证guest、tap/veth和生产网段真实断链，不能仅核对配置字段。

## 回退决策

| 阶段 | 行动 | 禁止事项 |
|---|---|---|
| T0前失败 | 保持原注册，按既有服务方法恢复原源；确认无目标新数据 | 不退注册、不删任何卷 |
| 源已退注册，恢复未开始/失败 | 停止并确认目标任务终止，保留部分目标卷；无目标业务写入时仅退目标注册，再恢复原源注册和原盘 | 不重复restore覆盖部分卷，不手工解锁进行中任务 |
| 目标尚未首次启动（或有明确获准的R0例外证据） | 目标停机/onboot0、归档并仅退目标注册，源恢复私有配置、原卷和网络；校验唯一身份再启动源 | 不同时启动；不把启动后业务变化当不存在 |
| 目标首次启动后默认已可能产生新写入 | 停写、停目标、做并验证T1备份；按最新数据恢复回源，或保留目标继续修复 | 不启旧源数据，不承诺T0副本包含迁后数据 |
| pve0失效/无法取T1 | 恢复到最近可读恢复点前，明确数据截止点并由用户决定是否接受损失 | 不声称RPO0或把旧盘当最新副本 |

## R0：无业务新写入的原盘回退

1. 目标正常停机/onboot0，确认无恢复/备份/迁移任务在运行；归档当前目标配置、卷清单、错误与数据截止点。
2. 该ID仍注册在pve0时，用已演练附录A仅退目标注册；保留目标卷。不执行destroy、pvesm free或全盘清理。
3. 确认ID在整个集群空闲；在原源节点用附录A restore与原私有SHA256恢复原配置，onboot保持0。核对原rootfs/mp、原IP/MAC、ACL/firewall，确认目标不运行后启动源。
4. 对原业务复验，再按原常开策略恢复onboot。目标残留卷和配置归档保留到另行清理授权。
5. VM108属于独立节点，pve0旧源已退注册并留置ID108。只有目标从未启动，或操作者基于完整书面证据明确接受丢弃无业务意义的验证副作用时，才能恢复源注册走R0；目标只要曾启动，默认必须走T1，即使当前关机。pve2目标须停止/onboot0并隔离，源才能恢复。

目标首次启动时间写入单一私有清单：源注册已退下也不得再次分配该ID；目标曾启动后默认T1。若例外走R0，须记录无业务新写入的证据及接受丢弃验证副作用的明确决定。

源配置含CT111无效unused0时，恢复原配置不等于修复该历史记录；原真实挂载必须逐项验证，不把该字符串当真实卷释放。

## R1：已有新写入的最新数据回退

1. 目标停全部写入并正常关机，保存最新业务状态；创建并验证T1全量备份，验证目标能读取，保留T0、目标盘与T1。T1失败则留在停止/保全状态，不启动旧源。
2. 刷新源的data/metadata、目标新盘实际字节和恢复峰值。源保留旧卷时可能装不下第二份数据，尤其CT111：其所在nvme-lvm LVM-thin池（约900GiB）已近满，不能直接再恢复一份800GiB。
3. 目标仍注册则先在原生锁下退下目标注册，保留目标盘；源不得先注册旧配置并启动。该ID在整个集群空闲后才恢复T1。
4. 有足够已批准的源空间时，恢复T1到新卷；无空间时停止。若操作者另行批准释放源旧卷，按本次清单逐个核对完整volid、node、owner、大小、无运行引用、T0/T1均可读且目标盘保留，再仅释放这些旧卷。**本手册不提供通配或VMID扫描删除命令；未获目标特定授权不得继续。**
5. 在pve1恢复VM用qmrestore到原local-lvm/nvme-lvm映射；CT118恢复local-lvm:24。CT111恢复T1时显式rootfs=local-lvm:8、mp0=nvme-lvm:900,mp=/srv/timemachine,backup=1，保持非特权1；源ext4可用字节及thin块/metadata预算须容纳T1全部文件，不能只看900逻辑值。
6. 原生恢复命令与正向一致，只替换到记录的T1和原节点/存储；多存储VM若单一--storage不能保持原布局，先在源选择已批准的统一存储并重算容量，或按正式恢复映射方案修订后再执行，不现场猜测。恢复不启动，按完整性/功能/管理验收，再开放源为唯一写入者。
7. VM108跨独立节点如有新数据，同样先保存T1再恢复源；源原VM108占ID时不得force覆盖，先批准对应配置交接并确认目标不会启动。


本路径执行命令紧接下一节“R1精确恢复映射与破坏性释放边界”，禁止跳到收尾后再找恢复命令。

## R1精确恢复映射与破坏性释放边界

以下命令仅在T1已完整验证、目标停止且该ID已在整个集群退注册、源容量账本通过后执行；均不加force，不自动启动。

| 返回对象 | 执行节点 | 命令 |
|---|---|---|
| VM112/113/115 | pve1 | qmrestore "$T1_VOL" "$VMID" --storage nvme-lvm --unique 0；随后qm set "$VMID" --onboot 0 |
| VM114/116/117 | pve1 | qmrestore "$T1_VOL" "$VMID" --storage local-lvm --unique 0；随后qm set "$VMID" --onboot 0 |
| CT118 | pve1 | pct restore 118 "$T1_VOL" --rootfs local-lvm:24 --unprivileged 1 --onboot 0 --start 0 |
| CT111 | pve1 | pct restore 111 "$T1_VOL" --rootfs local-lvm:8 --mp0 nvme-lvm:900,mp=/srv/timemachine,backup=1 --unprivileged 1 --onboot 0 --start 0 |
| VM108 | pve0 | qmrestore "$T1_VOL" 108 --storage vmdata --unique 0；随后qm set 108 --onboot 0；源ID108原注册须先按获准交接释放 |

这些源映射来自当前配置；实施前有新增盘/跨池分布就先修订表，不猜映射。备份含原net字段时恢复到原桥并核对，仍先执行附录C隔离。T1反向恢复必须使用最新数据，而不是T0变量。

容量在首次向目标开放写入前选定并签入变更单：A=源有足够空间再放一份T1；B=无第二份空间、但已明确批准仅释放清单中的旧源卷后恢复T1；C=两者均不满足，接受保全目标继续修复，不能承诺即时回源。不得默认CT111满足A分支条件。B释放后的900GiB ext4实际可写及thin data/metadata仍须容纳最高800GiB文件数据及元数据；不是只比较800<900。

B分支会破坏原源盘，必须有针对确切volid的新授权；当前并未授权。下面仅给CT111当前已识别两盘的条件命令，不涉及CT111的已证实无效unused0记录，也不涉及任何pve0卷：

```bash
# pve1 only, DESTRUCTIVE: run only under branch-B target-specific authorization.
[[ "$(hostname)" == pve1 ]] || exit 1
[[ "${MIGRATION_OLD_SOURCE_FREE_APPROVED:-}" == YES ]] || exit 1
: "${T1_VOL:?Verified latest recovery point required}"
# Before each command: compare private manifest, verify no active reference/mount,
# verify T0/T1 readable and pve0 target disks remain preserved. Stop on any mismatch.
pvesm free 'local-lvm:vm-111-disk-0'
pvesm free 'nvme-lvm:vm-111-disk-0'
```

不得把此例推广为循环删除112–118；每个其他guest若要释放旧卷，须先列出其本次实际全部volid并取得对应授权。释放后R0原盘回退失效，只能使用T0/T1恢复；在记录中明确这条不可逆边界。

## 回退结果与收尾

任何部分回退都记录：恢复点、数据截止点、是否有数据损失、实际活动节点、遗留卷和禁用的自动化。备份/配置文件/hash存在不证明服务已经恢复，必须完成业务复验。

正常观察通过后，原盘与目标失败残留卷的清理只按精确manifest另行授权，不能使用guest destroy或destroy-unreferenced-disks扫描同ID的所有存储；因源/目标盘都可能同属原VMID，批量扫描可误删生产目标。pve1关机后若仲裁失败，应恢复该节点与见证路径；不得临时降票顶替验收。
