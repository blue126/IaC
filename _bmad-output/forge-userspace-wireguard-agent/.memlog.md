- (decision) 按常见做法：默认自动检查并下载更新，安装前需员工手动确认；员工可关闭自动检查，改为手动检查更新（取代之前的静默自更新）

- (crack) Docker 方案：Mac 上容器跑在 Linux 虚拟机里，WireGuard 网卡建在虚拟机内，Mac 本身访问不到 10.234.0.2，只能靠 127.0.0.1 端口发布，与用户态代理同样的语义代价；另需 Docker Desktop/OrbStack（安装要管理员、常驻虚拟机占内存），发布 1001 个 UDP 端口很重
- (kill) Docker 方案否决：Mac 上与用户态代理语义代价相同，另加 Docker Desktop 安装与常驻虚拟机
- (lock) 客户端内核选特权守护进程：安装时授权一次装 root LaunchDaemon 起系统 WireGuard 网卡并提供仅本人可访问的控制套接字；访问方式（10.234.0.2、desktop_url、VM nginx、ssh 配置）全部不变
- (kill) 原始想法“完全免 sudo 的用户态代理”不采用：一次授权可接受后，它为免授权付出的访问方式改动（127.0.0.1 转发、nginx、证书警告、mosh 端口段）不值得
- (lock) 守护进程内嵌 wireguard-go，自己管 utun 网卡和 /32 路由，不依赖 Homebrew wireguard-tools、bash 4 和 wg-quick
- (lock) 控制套接字白名单：status、up/down（无参数）、route（同现有校验）、check-update/apply-update（守护进程自己下载并验签，客户端不能传路径或二进制）；连接方 uid 用 getpeereid 核对为安装时记录的员工；私钥只放 root 目录
