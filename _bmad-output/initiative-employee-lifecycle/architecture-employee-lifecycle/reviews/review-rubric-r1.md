该 spine 暂不宜通过 Reviewer Gate：目标方向清楚，但恢复放行、资源回收、D1 清单契约和防火墙并发边界仍存在会让下游实现分歧的缺口。

1. **high — 恢复流程在核对当前事实前恢复旧配对。**
   **位置：** AD-32；配置总览恢复表第 3～5 步。
   **原因：** 表中先运行 role，再由旧账本填充 nft set，最后才推送当前到期快照、按 D1 清理身份。公开的 `portal.yaml.j2` 设置了 `restore_state: true`，role 会启动 Portal。因此，备份之后退役、改址或到期的身份可能先恢复接入；AD-10 又允许地址复用，使旧配对指向新员工资源成为需要防止的情况。单次 set 替换的原子性不能保证恢复顺序安全。
   **具体修复：** 明确恢复期间保持员工转发关闭；完成当前 D1 身份对账、凭据匹配、最新到期快照和配对校验后，才填充最终 set 并放行。任一步失败都维持隔离。将这一顺序同时写入 AD-32 和恢复表。

2. **high — IP 变更预案尚不可执行，却未成为恢复能力的上线前置。**
   **位置：** AD-32；`oci-hub-ip-change.md` 的“现在还不能完整执行”“需要提前准备”。
   **原因：** runbook 明确缺少按新 endpoint 批量重建设备包和批量更新已有 VM 的入口。AD-32 的上线前置只要求验证同实例换卷保留 IP，未覆盖实例无法保留的恢复分支。完成该演练仍不能证明 IP 改变时能够恢复服务。
   **具体修复：** 将“全量切换 endpoint” story、完整 DNS 清单及批量切换验证列为启用该恢复分支的前置条件；完成前，明确标注新实例恢复分支受阻。保留临时 IP 的决定本身无需改变。runbook 对 `reissue` 的描述涉及私有代码，目前只能视为待验证断言。

3. **high — AD-28 没有区分 Terraform 所需的完整 VM 意图清单与员工在册视图。**
   **位置：** AD-2 的 VM 所有权行；AD-28。
   **原因：** VM 记录必须先于 Terraform 存在，但 `catalog()` 又排除开户中的记录，且“由现有字段推导在册”没有给出具体谓词。不同模块可以合理地生成不同清单。Terraform 对 map 中缺失的条目可能计划销毁；读取失败、部分读取和合法空清单必须能明确区分。公开开户说明现有约束是 D1 不可读时停止写入，roster 缺失时不调用 Terraform。
   **具体修复：** 定义两个查询契约：完整 VM 意图清单用于生成 var-file；统一的员工在册谓词用于生命周期消费者。明确查询完整性、版本与失败行为，禁止把读取失败转换为空清单。迁移时冻结旧 roster 写入，导入并核对完整 Terraform plan 后一次切换权威来源。

4. **high — 退役后的回收条件与 HAPI 残留清理条件不一致。**
   **位置：** AD-10；AD-23。
   **原因：** AD-10 允许删除记录后回收地址，并声称 `hapi-sync` 失败时下一次 `enforce` 会让 route 下线；但 AD-23 明确规定 `enforce` 不送空名单。退役最后一名员工时，该兜底不能成立。对于其他退役，route、令牌及 Access 清理也可能延迟到每日同步，而地址已进入可复用池。
   **具体修复：** 定义可回收检查点：确认所有指向原 VM/地址的授权和路由已撤销后才释放分配。允许经过新鲜、完整 catalog 读取确认的空名单执行清理，或提供明确的退役撤销路径。保留地址可复用的决定。

5. **high — AD-26 的“已加载规则”不足以证明规则对应当前主机对象。**
   **位置：** AD-26 的对象读取、规则加载和 pre-start hook 约束。
   **原因：** 取消独立策略与 generation 后，规则生成、SDN/VM 配置变化和启动检查之间仍可能交错。Rule 没有要求它们共享锁，也没有规定 hook 如何证明已加载规则覆盖当前对象。旧规则存在与当前配置受保护是不同的条件。
   **具体修复：** 定义对象读取、渲染、加载和启动校验的共同串行边界；hook 核对当前对象摘要与成功加载的规则摘要相符。明确运行中网络配置变化必须如何触发重算，以及校验失败时如何阻止受影响 VM 继续使用未覆盖的网络。

6. **high — nft set 重载保留元素与 `pairs` 更新缺少共同并发契约。**
   **位置：** AD-27。
   **原因：** `pairs` 是唯一配对调用入口，但 role 的规则重载同样会修改包含 set 的规则结构。“读取现有元素后保留重载”与一次并发的配对替换可以各自原子成功，最终却恢复旧元素。执行器运行锁不能自动约束 OCI 上由 Ansible 发起的重载。
   **具体修复：** 要求 `firewall.py` 的规则重载和 `pairs` 操作使用同一把 Hub 本机锁，覆盖读取、保留、替换和回读全过程。首次部署还需定义兼容握手：公开旧 `boundary.py` 不支持 `pairs`，所以“先发布新 executor，再切规则”必须说明新 executor 在旧防火墙版本上如何安全等待。

7. **high — 延期自动同步可以成立，但“最新 checkout”不能充当执行一致性保证。**
   **位置：** AD-30；Deferred“执行器 IaC 自动同步”。
   **原因：** 公开 `remotecc-ops-runtime` 配置只给私有 `remotecc` 仓库设置了 `run_lock`；`iac` 的 post-receive 会直接 checkout `/srv/iac`。因此，运行前人工确认最新，仍不能防止执行期间代码、模板或 AD-25 的静态参数被切换。
   **具体修复：** 自动 CI/CD 继续延期；现在就要求运行绑定批准的 IaC commit，并通过共同运行锁或不可变 checkout 防止中途替换。审批摘要应明确覆盖实际使用的 IaC 代码与配置版本。

8. **medium — AD-27 与既有 timer 写入限制直接矛盾。**
   **位置：** AD-1、AD-9、AD-27。
   **原因：** AD-1 说 OCI timer 只能增删 Portal 原因；AD-9 进一步规定除此之外不做任何写入；AD-27 却要求每个 quota 周期纠正 nft set，并在开机后填充。下游无法同时遵守这些 Rule。
   **具体修复：** 区分“到期原因处理”的写权限和 quota 周期经本机 executor 执行的配对对账权限，修改 AD-1、AD-9 的限制范围；继续禁止 timer 调用家中系统。

9. **medium — 从零重建表给出了路径，但账本恢复语义仍明确未决定。**
   **位置：** 配置总览“从零重建”列；Deferred“OCI Hub 从零重建”；AD-32。
   **原因：** 表中使用 `--new-hub` 后从 D1 重新登记身份，看起来是一条可执行备用路径；Deferred 却说明账本丢失后的处理待定，且部署合同禁止重新初始化为零。D1 身份和 `paid_through` 不能恢复月用量、计数基线及 Portal 人工状态。公开开户说明也明确要求回退时保留更新后的用量与人工操作。
   **具体修复：** 将该列标为受阻流程，并列出所缺的账本、Portal 状态恢复决策；或补齐恢复来源、允许的数据损失、未知用量处理及放行条件。不能以重新登记身份代表业务状态已经恢复。

10. **medium — `service-egress.json` 的延期决定会保留第二份员工授权来源。**
    **位置：** AD-26；AD-2 的所有权表。
    **原因：** 公开 `boundary.py` 的 `load_service_egress()` 会把文件中的 HAPI/Tunnel grants 与主配置做并集合并。AD-26 一面规定不设员工层文件、废弃 `hapi_*_grants`，一面把该文件能否退役交给实现 story。若只是继续读取它，旧授权仍会参与生成规则，违反新的所有权约束。
    **具体修复：** 在 spine 中确定迁移后的来源：动态员工 grants 必须停止从旧文件读取；确需保留的静态例外需明确字段和唯一 IaC 来源。将旧文件内容盘点、授权等价核对及停读列为切换条件，具体代码仍由 story 实现。

11. **medium — 设备包存储契约在新所有权表和退役流程中仍指向 R2。**
    **位置：** AD-2“私钥”行；AD-10；AD-17；Deferred“R2”。
    **原因：** AD-17 和 Deferred 已决定当前设备包存 D1，AD-2 却说在 R2 临时存放，AD-10 也只列出删除 R2 设备包。实现者可能删除错误存储位置，或保留含私钥的 D1 包。
    **具体修复：** 统一称为 Worker 管理的设备包存储，明确当前后端是 D1、未来可换 R2；退役按员工和设备删除实际存储对象及下载授权。同步修正能力映射中仅写 R2 的描述。

12. **medium — 申请网站的现有 Rule 不支持新的 D1 写入职责。**
    **位置：** AD-13；AD-21；AD-2、AD-28。
    **原因：** AD-13 明确“不提供登录或员工状态查询”，与 AD-21 冲突；其管理接口又“只提供”申请和设备包操作，未包含员工 catalog、VM 记录的读写。AD-28 要求在 Terraform 前可靠写入 VM 记录，却没有一条符合 AD-13 的受控接口路径。
    **具体修复：** 更新 AD-13，使其与已决定的登录、自助状态和 catalog/VM 管理职责一致，并明确这些写入仍仅由执行器认证调用。D1“不存凭据”的表述也应明确如何容纳 AD-17 已选择的设备包存储例外。

13. **medium — 执行器和 D1 的恢复边界仍是整个运维维度的空白。**
    **位置：** AD-12、AD-15、AD-28、AD-32；Deferred。

    **具体修复：** 至少将这些恢复责任明确列为 open item，并指定备份来源、允许损失范围、单执行器恢复步骤及重新允许写入的条件；说明 generation 如何避免随执行器备份回滚。无需在本 spine 中展开备份实现。
