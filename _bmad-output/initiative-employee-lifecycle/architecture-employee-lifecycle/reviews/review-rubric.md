暂不通过：此次更新明确了多数所有权与迁移边界，但续期传播、退役回收及恢复契约仍存在会导致系统事实分歧的缺口。

1. **high — 控制台续期没有传播到 OCI 快照的路径。**
   **位置：** spine AD-2 `paid_through` 行、AD-9、AD-12、AD-16。
   **为什么重要：** AD-2 允许管理员直接在 D1 控制台续期，但 AD-12 只要求执行器修改后推送快照，没有定义如何发现控制台修改。因此，执行器可能按新日期恢复 VM 和 HAPI，OCI timer 却继续依据旧快照施加 `expired`。
   **具体修复：** 明确所有 `paid_through` 写入口都自动推进 generation，并由执行器定期读取权威数据、补推快照；定义推送失败的报告与重试。AD-10 所依赖的“控制台续期必然改变 generation”也应由数据库约束或统一写协议保证。

2. **high — 地址和 VMID 的回收早于资源清理完成。**
   **位置：** spine AD-10、AD-28。
   **为什么重要：** 退役首先删除 VM 记录，同时规定资源“随记录删除回到池中”；后续才删除 Portal 身份、VM、VNet、密钥和 HAPI 投影。若流程在提交点后中断，下一次开户可能复用仍被旧资源占用的标识；旧退役记录续跑也可能触及新分配。单次运行锁不能解决跨运行的复用问题。
   **具体修复：** 保留退役提交点，但在运行记录中持续保留分配占用，直到相关资源和接入投影清理完成并核验后才释放；续跑操作绑定原资源身份，不能仅按已可复用的 VMID 或地址定位。

3. **high — 最后一名员工退役时，承诺的 HAPI 兜底不会执行。**
   **位置：** spine AD-10、AD-23。
   **为什么重要：** AD-10 承诺 `hapi-sync` 失败后下一次 `enforce` 会让 route 下线；AD-23 却禁止 `enforce` 发送空名单。最后一名员工退役后，合法的 catalog 正是空名单，旧 route 会至少残留到下一次成功的 `hapi-sync`。地址复用会放大这一问题。
   **具体修复：** 区分“成功读取的权威空名单”和“读取失败”，允许前者清除路由；或者规定退役必须完成单独的路由撤销，失败期间禁止释放相关地址。

4. **high — 恢复顺序没有遵守新旧应用与防火墙的兼容前置。**
   **位置：** spine AD-27、AD-31、AD-32；配置总览恢复步骤 3—5。
   **为什么重要：** AD-27 要求先发布支持 `pairs` 的私有服务，再切换防火墙；恢复表却直接在恢复启动卷后运行当前 role，没有先核验或升级备份中的私有服务。跨越改名、配置字段或协议迁移的旧备份，可能留下无法读取新配置、无法填充 set 的旧服务。
   **具体修复：** 恢复流程先核验备份中的应用版本、配置和账本兼容性，再按 AD-27 的顺序执行受控升级；将服务启动、配置兼容和配对投影一致纳入开放 NSG 前的明确门槛。

5. **high — D1 身份对账不足以证明恢复后的账本和接入状态正确。**
   **位置：** spine AD-2、AD-27、AD-32；配置总览“全部通过才打开 NSG”。
   **为什么重要：** D1 不拥有月用量、采样基线或 Portal 人工停用原因。启动卷回退会同时回退这些事实，补登记和删除身份不能恢复备份之后的用量及人工操作。公开仓库当前文档也要求保留月账，不能用恢复覆盖更新后的用量和 Portal 操作，见 `docs/deployment/oci-hub-provision.md:98–102`。
   **具体修复：** 明确整机恢复允许丢失哪些事实、如何处理回退的用量和人工原因，以及计数基线如何重新建立；给出开放接入的核验条件。无法恢复的部分应记录为明确接受的数据损失或待处理项，不能由身份对账成功隐含批准。

6. **high — 执行器与 D1 恢复延期会直接破坏现有一致性保证。**
   **位置：** spine Deferred“执行器和 D1 的恢复”；AD-1、AD-10、AD-12、AD-28。
   **为什么重要：** 这些数据分别承载审批、退役检查点、generation 和 Terraform 完整输入。若各自恢复到不同时间点，完整但较旧的 D1 清单仍可能导致删除付费 VM，旧检查点可能重放删除，较低 generation 则会被 OCI 拒收。“按现有私有备份处理”没有规定一致恢复边界，不能阻止这些分歧。
   **具体修复：** 可以延期自动恢复工具，但现在就应决定恢复后的写入冻结、权威来源、generation 延续、旧审批失效和全量对账规则；完成这些规则前禁止恢复后直接执行写命令。

7. **medium — timer 的写入限制排除了它必须执行的记账。**
   **位置：** spine AD-1、AD-9，与 AD-27“账本继续服务配额”冲突。
   **为什么重要：** AD-9 规定 timer 除 Portal 原因和配对校对外“不做任何写入”，但同一个 `oci-hub-quota.timer` 必须保存采样基线、月用量及审计。公开架构文档明确这些是 SQLite 事务写入，见 `docs/architecture/oci-employee-vpn-hub.md:290`。按新限制实施会停掉记账；保留记账又违反该 Rule。
   **具体修复：** 列出允许的本机写入：配额账本、必要检查点、接受的快照 generation，以及配对投影；继续明确禁止 Terraform、BWS、PVE 和家中系统写入。

8. **medium — “在册”尚未成为可执行的查询契约。**
   **位置：** spine AD-28，关联 AD-3、AD-10、AD-20、AD-23。
   **为什么重要：** 文档要求在册谓词只在 `catalog()` 定义，却没有给出谓词本身。开户中的 VM 必须进入全量查询，但何时进入 HAPI 名单、删除 VM 记录的提交点是否立即退出 catalog，都没有明确。这些差异会改变接入和退役行为。
   **具体修复：** 用现有事实写出唯一的在册判断，并明确开户各阶段、退役提交点之后两类查询分别返回什么；保持无需新增生命周期状态字段的决定。

9. **medium — 恢复时“关闭 NSG”与随后“plan 无漂移”缺少协调。**
   **位置：** spine AD-32；配置总览恢复步骤 1—2。
   **为什么重要：** WireGuard NSG 入站由 Terraform 管理，公开实现见 `terraform/oci/oci-hub.tf`。若恢复时手工移除这些规则，随后的 plan 会显示恢复规则的差异；直接 apply 又会提前解除隔离。
   **具体修复：** 指定维护关闭方式，并把检查要求改为“除已批准的隔离差异外无其他漂移”，或将维护开关纳入 Terraform 输入；明确该阶段不能通过 apply 提前开放入站。

10. **medium — `reissue` 在 spine 与 IP 预案中的含义冲突。**
    **位置：** spine AD-17；`oci-hub-ip-change.md:9`。
    **为什么重要：** AD-17 说 `reissue` 会重新生成设备包；预案说它重发磁盘上的旧包，不检查 endpoint。这会使后续实现和恢复操作对同一命令作出不同假设。该发现是文档契约冲突，私有实现无法独立验证。
    **具体修复：** 明确当前 `reissue` 的行为，并定义 endpoint 变更时真正重建设备包的命令与校验；将其完成条件关联到新实例恢复的阻塞项。

11. **medium — named tech 的“verified-current”条件尚无可核验证据。**
    **位置：** spine Stack，尤其 bpg/proxmox、Semaphore 和运行时“当前”版本。
    **为什么重要：** 公开源码能确认 bpg/proxmox `0.70.0`、oracle/oci `8.3.0` 和 ansible-core 范围等配置，但不能证明“2026-11 最新”“最新稳定版”或执行器实际安装版本。AD-29 的 provider 能力判断也没有随输入提供核验依据。
    **具体修复：** 给这些判断附上核验日期、官方来源和结果；将已配置版本、实际运行版本与待选目标版本明确区分。本次授权仅允许读取指定目录，无法独立联网补齐这些核验，不能判定其已满足 checklist。

12. **low — 新增强制纠正行为尚未同步到旧的人工操作规则。**
    **位置：** spine AD-2“VM 电源状态”、AD-9、AD-11、AD-16。
    **为什么重要：** AD-11 无条件说页面手工启用合法且执行器不纠正，但 AD-9 要反复施加 `expired`，配额规则也会重新停用；AD-2 说电源“只由执行器”操作，AD-16 又明确允许管理员在 PVE 操作。读者无法从规则文字判断例外范围。
    **具体修复：** AD-11 明确人工原因受保护、到期和配额原因仍由对应规则纠正；AD-2 将电源事实所有者与允许的人工操作入口分开表述。

13. **low — 生命周期“不持久化”的绝对规则与展示副本冲突。**
    **位置：** spine AD-2“小程序展示的员工状态与到期日”、AD-3、AD-21。
    **为什么重要：** AD-3 禁止任何组件持久化生命周期状态，AD-2 和 AD-21 却要求两端保存执行器推送的状态副本。派生缓存可以成立，但当前文字没有给出例外及其权威边界。
    **具体修复：** 明确允许不可反向写入事实所有者的展示缓存，并规定来源、更新时间及过期显示方式；继续禁止把缓存状态作为执行依据。
