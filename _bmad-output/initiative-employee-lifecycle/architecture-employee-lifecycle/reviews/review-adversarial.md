结论：这份 spine 尚不能通过一致性 Gate，以下六组实现可以分别遵守现有 AD，却在共享数据含义、状态传播或写入协调上发生冲突。

1. **high — D1 控制台续期与 OCI 到期执行采用不同事实版本**

   **单元 A：D1 管理端。** 按 AD-2 允许管理员直接修改 `paid_through`，并按 AD-10 同时改变 catalog generation。

   **单元 B：OCI 到期执行器。** 严格遵守 AD-4、AD-9、AD-12，只读取执行器经 SSH 推送的快照，不访问 D1；执行器仅在 `provision`、`renew`、`retire` 修改事实后推送快照。

   **冲突：** 管理员在 D1 控制台把员工续期到下月底，A 的写入完全合法，但没有任何 AD 要求该写入触发快照推送。B 继续依据旧快照施加 `expired`；与此同时，AD-16 的 `enforce` 从新 catalog 看到未到期，可以恢复 VM 和 HAPI。一次合法续期因此产生两个接入系统相反的决定，且 WireGuard 的旧决定可以无限持续。

   **关闭漏洞的规则：** 收紧 AD-2、AD-12：或者禁止控制台直接续期，统一使用 `wsctl renew`；或者明确由执行器定期读取新 catalog generation，并在规定时间内推送整份快照，覆盖控制台修改。应区分“D1 已保存”与“OCI 已接受该 generation”，让管理员能确认续期实际生效。

2. **high — 配对接口的“VM 地址”可以合法指向两种不同网络**

   **单元 A：网站配对接口。** 遵守 AD-2、AD-13、AD-28，从 D1 的全部 VM 记录生成配对，包含开户中的记录；把“VM 地址”解释为 AD-26 根据 VMID 算出的工作区物理 IPv4。

   **单元 B：Hub 配对适配器与防火墙。** 遵守 AD-25、AD-27，把 `workspace` 解释为工作区 WireGuard overlay IPv4，按既定 JSON 形状提交 nft 配对元素。

   **冲突：** AD-13 只要求返回设备和 VM 的地址；AD-27 的字段只有 `<IPv4>`，没有指定地址所属网络。A 返回的物理 IPv4 在结构上有效，B 可以成功安装该元素，但真正从 `wg-workspaces` 收到的 overlay 流量不会匹配。已有公开源码明确区分物理地址和 overlay，因此这不是仅有命名差异。

   **关闭漏洞的规则：** 收紧 AD-13、AD-27、AD-28：网站配对接口也使用明确的版本化协议；规定 `device` 为设备 WireGuard 隧道 IPv4，`workspace` 为 VM 的 overlay IPv4，均为不带 CIDR 的地址，禁止使用 VMID 派生的物理地址。关系必须由 D1 中明确的设备归属与 VM 关联生成。

   **依据：** 公开仓库分别把物理地址用于 `ansible_host`、把 overlay 用于 Spoke（`terraform/remotecc/oci-hub-workspace.tf:90`）；Hub 的工作区配对目标要求经 `wg-workspaces` 路由（`scripts/oci-hub/boundary.py:383`）。

3. **high — nft 本机锁不能阻止旧配对快照最后覆盖新配对**

   **单元 A：定时配对同步。** 遵守 AD-4、AD-13、AD-27，经只读接口取得完整配对，再调用唯一的 `firewall.py pairs`，在本机锁内原子替换元素。

   **单元 B：变更后的即时配对同步。** 同样遵守 AD-27，在 `readdress` 或 `retire` 后立即读取最新完整配对，并通过同一个入口和同一把锁替换元素。

   **冲突：** A 先取得旧配对，但在调用 `pairs` 前暂停；B 随后取得新配对并完成替换；A 最后取得锁，把旧配对重新装回。两个 nft 事务都完整且互斥，仍然发生版本倒退。AD-27 的协议没有 generation，也没有要求从远端读取到本机提交的整个过程串行化。配合 AD-10 允许地址回收，这不仅会阻断正常连接，还可能重新放行已经撤销的地址关系。

   **关闭漏洞的规则：** 收紧 AD-13、AD-27：配对响应必须来自同一 D1 快照并携带单调 generation；Hub 在同一临界区内检查版本、替换元素、记录已接受版本，拒绝旧版本。重试相同版本也必须有明确规则。另一种可行约束是强制所有同步任务从发起读取直到完成替换全程串行，并禁止使用旧响应或缓存回放。

4. **high — 退役已提交的员工仍可能被生命周期执行器重新启用**

   **单元 A：D1 catalog 查询。** 遵守 AD-2、AD-3、AD-28，仅在 `catalog()` 一处定义在册谓词，例如依据 `employees` 中现有员工资料及 `paid_through` 是否齐全判断在册，不新增生命周期状态字段。

   **单元 B：退役与到期执行器。** 退役按 AD-10、AD-28 先条件删除 VM 记录，把它作为不可撤回的提交点；`enforce` 和 `hapi-sync` 按 AD-16、AD-20、AD-23，依据刚读取的 catalog 和到期日决定电源及 HAPI 可用性。

   **冲突：** 退役成功删除 VM 记录后、删除实际 VM 和员工记录前中断。管理员此时在 D1 修改 `paid_through`，按 AD-10 已不能撤回退役，但员工记录仍满足 A 的在册谓词。下一轮执行器会把它当作已续费员工，恢复仍存在的 VM 和 HAPI；恢复退役流程又会继续删除它。相同事实同时表示“不可撤回地删除”和“应当恢复使用”。现有 AD 没有规定在册谓词必须排除已删除 VM 记录的员工。

   **关闭漏洞的规则：** 收紧 AD-28：明确在册谓词至少要求对应 VM 记录存在；AD-10 的提交事务必须使员工立即退出所有可用性名单。提交后的续期写入应被条件拒绝或明确返回“退役已提交”，不能保存一个会被普通生命周期执行器解释为可恢复的续期结果。该约束可由记录关系推导，无须新增生命周期状态字段。

5. **high — 恢复隔离与 Terraform 同时决定同一组 NSG 规则**

   **单元 A：Hub 恢复流程。** 遵守 AD-32 和配置总览，先关闭 NSG 的 WireGuard 入站，恢复启动卷；只有全部对账通过才重新开放，失败就保持关闭。

   **单元 B：OCI Terraform 配置。** 遵守 AD-2、AD-25、AD-32，依据现有入站来源变量管理 NSG。一次另行批准的正常 Terraform apply 会把线上规则恢复为声明的允许状态。

   **冲突：** A 的临时隔离没有进入 Terraform 的期望状态，也没有持久化的恢复锁约束 B。恢复失败或流程中断后，B 可以合法地把隔离当作漂移修复，提前开放旧身份。即使只执行配置总览第二步的只读检查，关闭由 Terraform 管理的入站规则也会产生预期漂移，与该步要求“确认无漂移”冲突。

   **关闭漏洞的规则：** 收紧 AD-32、AD-25：定义 Terraform 所有的持久化恢复隔离开关，以及唯一的开启、解除入口；恢复期间所有 NSG apply 必须服从该开关，解除必须依赖恢复验收。同步修改配置总览，明确隔离期间允许的精确 plan 差异，不能笼统要求零漂移。

   **依据：** 公开仓库已由 Terraform 管理这些入站规则（`terraform/oci/oci-hub.tf:39`）。

6. **medium — PVE 规则加载器与启动 hook 没有共享摘要契约**

   **单元 A：PVE 防火墙加载器。** 遵守 AD-26、AD-30，在本机锁内读取对象、渲染并加载规则；对参与规则生成的规范化安全字段计算“对象摘要”，记录到已加载规则中。

   **单元 B：VM 启动 hook。** 遵守 AD-26，使用同一把本机锁读取当前 SDN、VM 配置，对完整对象序列化后计算“当前对象摘要”，与已加载摘要比较，不同就拒绝启动。VMID 地址算法仍使用规定的同一算法和测试向量。

   **冲突：** 两者都实现了规定的摘要校验，却选择了不同的字段集合、排序或序列化形式。同一实际配置可以始终比较失败；完整对象中的非安全字段变化也可能阻止启动。共享地址测试向量只能验证地址算法，不能使摘要可互操作。

   **关闭漏洞的规则：** 收紧 AD-26：由一个共享实现同时提供加载器和 hook 的对象规范化及摘要计算；规定字段集合、稳定排序、编码、摘要版本和加载后摘要的保存位置。还应明确摘要是否绑定静态配置与渲染器版本，避免双方各自决定。

其余聚焦区域没有构造出独立、且双方均遵守全部相关 AD 的真实实现对：AD-1 的审批摘要、AD-29 的 SDN 所有权交接与明确接受的 pending 窗口、AD-30 的代码下发入口、AD-31 的配置及密钥来源，本次未发现额外冲突。IP 变更预案已经明确阻塞尚无入口的批量 endpoint 切换；Deferred 也明确承认从零重建及执行器/D1 恢复尚未定义，未将这些已声明的缺口重复算作发现。
