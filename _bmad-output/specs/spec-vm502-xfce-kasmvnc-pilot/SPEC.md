# VM502 XFCE + KasmVNC 试点实施规格

本文件与 companions 共同构成实施和验收契约。采用的 spine 为只读架构约束，保留 AD-1～AD-10。CAP-1～CAP-7 延续原员工工作区能力编号；本规格只描述试点增量，CAP-8 为本试点新增能力。

## Why

在保留员工专属 VM、sudo、个人订阅与登录态的前提下，用 VM502 验证完整图形桌面的日常开发体验。试点将既有浏览器通道替换为 XFCE + KasmVNC，同时迁移共享图形入口的 HTTPS，形成可复现的实施、隔离、切换和中国网络验收依据。

## Capabilities

- **CAP-1 — 个人开发环境**
  - **intent:** 员工在本人持久 VM 中使用图形开发环境并保留工具管理自主权。
  - **success:** VM502 的终端、Firefox、文件管理器可用；员工 sudo、项目文件及个人配置保留，既有 SSH/SFTP 回归通过。
- **CAP-2 — 个人订阅身份**
  - **intent:** 员工复用本人的浏览器登录态完成 Claude 订阅授权。
  - **success:** 登录成功、取消和超时均不关闭日常浏览器；没有并发 profile 写入；实际账号和订阅认证来源由本人确认。
- **CAP-3 — 本人资源与隔离**
  - **intent:** 登记设备只能访问所属员工资源，与其他员工及受保护网络隔离。
  - **success:** 本人访问成功；跨员工、未登记、撤销设备、身份头伪造、异源连接及后端直连均被拒绝，VM 外隔离回归通过。
- **CAP-4 — 澳洲运行与授权**
  - **intent:** 公司提供的 Claude 工作与授权使用澳洲个人 VM。
  - **success:** 本人确认授权页面、回调和 CLI 位于该 VM，并核对实际认证来源及相关请求的澳洲出口；本机只操作远端画面。
- **CAP-5 — 试点体验与共享接入**
  - **intent:** 用户判断中国实际网络下的桌面可用性，同时保留其他员工图形接入。
  - **success:** 同条件 noVNC/KasmVNC 对照及本人反馈完成；共享入口和 legacy 生命周期回归通过。本能力不承诺 5–10 人并发。
- **CAP-6 — 访问撤销与停用**
  - **intent:** 管理员按设备或员工收回访问，保留待按授权处理的数据。
  - **success:** 撤销使既有通道失效且不能重连，不停止同员工桌面；员工停用由外部阻断或停机并保盘。
- **CAP-7 — 独立生命周期与重连**
  - **intent:** 员工分别控制浏览器和完整桌面，并在断线后继续使用原实例。
  - **success:** 关浏览器不结束桌面任务；停桌面不终止 SSH 独立任务；多设备共享同一桌面；断线保留运行进程，VM 重启后手动启动，服务故障被明确报告。
- **CAP-8 — 可验证的变更与恢复**
  - **intent:** 管理员在保留现有环境的前提下验证、切换、维护和回滚试点。
  - **success:** 兼容证据、单一模式/profile、固定凭据代次、变更互斥、中断恢复及允许的切换/回滚组合均通过验收；失败不混装、重建或静默重启桌面。

## Constraints

- 所有实施遵守 adopted spine 的 AD-1～AD-10；实施细节见 implementation.md，验收以 acceptance.md 为准。
- 桌面组件只安装到 VM502；保留其实际 OS、规格、磁盘和 employee 身份。KasmVNC 种子版本为 1.5.0，安装前完成同 OS/架构、无员工凭据环境的安装与启动验证。
- 共享网关只在 WireGuard 私网监听 HTTP 8080 与 HTTPS 8443；8080 仅跳转到 canonical HTTPS 根入口。其他员工保持原 noVNC 后端和生命周期。
- 保留 sudo、正常公网开发出站、受管 SSH/SFTP 及 VM 外隔离；不增加本人 sudo 防绕行机制，也不承诺识别全部员工自建中继。
- 个人 OAuth、profile、后端凭据及 CA 私钥不进入代码、普通日志或设备交付材料；备份和恢复个人登录态副本遵守既有授权。
- 图形进程按需启动；断线与授权结束不拥有退出权；自动重启、自动开机启动和静默维护重启均不作为默认行为。
- 只读规格不授予安装依赖、创建验证基础设施、部署、重启、Terraform apply、提交或推送权限；静态或 PR 检查不写入受管环境。

## Non-goals

- 推广桌面到其他员工 VM、承诺多人容量或消除跨境 RTT。
- 自动系统迁移、跨发行版混装、源码编译、重建 VM502 或自动恢复旧 profile 覆盖新登录态。
- WebRTC/UDP、STUN/TURN、GPU/视频编码优化、IDE 基线、HA、集中桌面平台、自动证书平台或通用门户。
- 改写员工现有业务项目、替本人登录订阅，或把私有管理员工具发布到公共仓库。

## Success signal

acceptance.md 的适用必需项均有通过证据：VM502 可由所属设备经可信 HTTPS 使用完整桌面，身份/隔离/撤销与登录态语义保持，变更可中断恢复并回滚，其他员工 legacy 接入正常。本人从中国实际网络完成代表性开发操作、个人订阅授权和新旧体验对照并确认日常可用；尚未执行、前置不满足或失败的项目不能记为通过。

## Open Questions

- **Q-1:** VM502 的实际 OS/架构及本次可复用的已授权无凭据验证环境是什么？按 brownfield.md 的输入表确认后才能安装。
- **Q-2:** 本次在用登记设备、浏览器及中国网络 UAT 操作者是什么？网关切换前须确认这些设备的 CA 信任与新入口。
- **Q-3:** 本次维护窗口、工作保存确认及既有个人 profile 备份/恢复许可是什么？未明确前不执行对应维护或凭据副本操作。
