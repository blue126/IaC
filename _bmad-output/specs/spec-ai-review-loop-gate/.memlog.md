- (direction) 使用 headless express 模式，根据完整对话与当前仓库事实生成全链路方案。

- (decision) 保留 Claude 为主审查器；GitHub Copilot Approval 仅作为可选替代 gate，不作为首期依赖。
- (capability) CAP-1：每个 PR HEAD SHA 都运行按变更范围选择的无部署确定性验证；当前 SHA 的必需检查全部通过才成功。
- (capability) CAP-2：Claude 对 PR 创建及每个新 HEAD SHA 自动复审；发现可修复问题时触发受限修复器，提交后再次复审，直到通过或安全停止。
- (capability) CAP-3：AI review gate 为当前 HEAD SHA 产生机器可读 required check，仅在 Claude 结构化结论无阻断发现且审查执行成功时通过。
- (capability) CAP-4：GitHub Ruleset 阻止直接写 main、强推和绕过必需检查；满足 gate 后由 GitHub auto-merge 执行 squash merge。
- (capability) CAP-5：合并后删除远端任务分支并清理临时 run 与 artifact；本地 worktree 仅在已合并、干净、无未推送提交且无活动进程时清理。
- (capability) CAP-6：main push 可启动 Jenkins，但自动流程不得批准 Terraform Apply 或 Ansible Deploy；任何外部写入仍需独立人工批准。
- (constraint) 禁止使用 pull_request_target 执行 PR head；含写 token 或模型凭据的 job 仅处理同仓库可信任务分支和不可变 HEAD SHA。
- (constraint) 修复提交必须使用专用 GitHub App 身份而非默认 GITHUB_TOKEN，以保证新 push 能触发 synchronize 复审并限制权限。
- (constraint) 自动循环最多三轮；重复指纹、不可修复结论、验证失败、冲突、敏感路径或权限异常立即停止并请求人工处理。
- (constraint) PR validation 不得 deploy、publish、apply、push image、发布制品、读取生产 secrets 或写入外部系统。
- (constraint) AI 审查只补充确定性检查，不得替代 Terraform、Ansible、文档和仓库脚本验证。
- (constraint) 现有 AGENTS 禁止自动 commit、merge 和删除分支；用户已授权为专用自动化主体增加范围明确的例外，其余主体继续受禁令约束。
- (decision) Ruleset 要求 PR、当前 SHA 的 repo-validation 与 ai-review-gate、解决全部 review conversation、阻止 force push，并启用 squash auto-merge。
- (decision) Terraform PR 检查包括 fmt 和 backend-disabled init/validate；plan 保留给 Jenkins，避免 PR gate 读取生产凭据或调用生产控制面。
- (decision) Ansible PR 检查包括 YAML、ansible-lint 和 playbook syntax-check；依赖以仓库锁定版本安装在临时 GitHub runner，不复用生产 Vault 或动态 state。
- (decision) Jenkins 风险与门槛 2 分离：前者控制 main 合并后的交付副作用，后者控制合并前代码质量；两者都必须满足但不能互相替代。
- (assumption) 假设首期仅支持同仓库、由用户或已批准 agent 创建的 PR，不自动修复 fork PR。
