# Evidence Model

本 companion 定义 CAP-1 至 CAP-4 共用的 truth priority、evidence gate、审计记录和 PR 契约。

## Complete Evidence Loop

一个候选文档偏差只有同时具备以下内容才算证据闭环：

1. 待核验的文档关键陈述及其位置；
2. 组件管理边界，以及证明相关 IaC 代码仍有效管理该组件的证据；
3. 不影响生产的只读观察，包含方法、目标、时间与结果；
4. 文档、代码和生产状态的对照结论；
5. 拟议修改、修改原因和查阅资料；
6. 改后验证动作与结果。

缺少任一项时，候选项不得进入自动修复路径。

## Truth Priority

| 证据情形 | 事实解释 | 允许动作 |
|---|---|---|
| 有明确且有效的 IaC 管理代码，生产与代码一致，文档不一致 | 文档漂移 | 证据闭环后可修文档并开 PR |
| 有明确且有效的 IaC 管理代码，设计文档与代码冲突，生产与代码一致 | 设计文档漂移 | 证据闭环后可修文档并开 PR |
| 有明确且有效的 IaC 管理代码，生产与代码不一致 | Production drift | 不改文档；升级人工 |
| 代码不管理组件，且非管理边界已经明确 | 生产状态代表现实 | 证据闭环后可修正文档偏差 |
| 代码管理关系或有效性不明 | 无法确定事实来源 | 不改文档；升级人工 |
| 代码未覆盖且设计文档未声明管理边界 | 管理归属不明 | 不改文档；升级人工 |

## Runtime Evidence

- 服务：验证可访问性。
- VM、container、物理机：验证可达性，并核对实际资源与代码声明。
- 单次失败：不得推断废弃或漂移，必须安排跨时段重试。
- 跨时段持续失败：不得推断废弃，必须升级人工。

所有观察必须只读、无影响、无破坏，并能够由工作记录追溯。

## Gate Outcomes

| Outcome | 条件 | 系统行为 |
|---|---|---|
| `consistent` | 三方证据一致 | 记录无变更结果 |
| `document_drift` | 事实来源明确，生产证据支持有效代码或已确认的非管理现实，且文档不一致 | 验证闭环后修改文档并开启单一问题 PR |
| `production_drift` | IaC 管理范围内生产状态偏离有效代码 | 保持文档不变并升级人工 |
| `unresolved` | 证据缺失、冲突、边界不明、代码有效性不明或持续不可达 | 保持文档不变并升级人工 |

## Audit Record

每次审计至少记录：

- 检查的文档陈述和位置；
- 查阅的代码、设计资料和生产观察；
- 管理边界与 truth-priority 判定；
- gate outcome 及理由；
- 做了哪些更改，以及为什么；
- 是否执行改后验证、验证方法和结果；
- 未修改时的无变更结论或人工升级原因。

## Automatic PR Contract

- 一个 PR 只修复一个可独立验证的文档偏差，不夹带重构、格式清理或其他顺手修改。
- 修改后的描述必须逻辑自洽，并明确区分 design target、code declaration 与 production state。
- 沿用目标文档现有章节结构、术语、命名和 Markdown 格式。
- PR 必须包含完整 audit record，并引用具体来源和验证结果。
- PR 只开启供审阅，不自动合并。
