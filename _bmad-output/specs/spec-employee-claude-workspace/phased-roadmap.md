# 第一阶段之后的路线图

本文件记录阶段目标。2026-10-22 用户明确同意将已部署授权画面扩展为日常浏览器，提前实施第二阶段这一最小能力，见 SPEC.md 的 CAP-7；第一阶段本人 OAuth 和真实任务验收继续进行，第三阶段 IDE 尚未启动。

| 后续阶段 | 目标与前一阶段的关系 |
|---|---|
| 第二阶段：浏览器 | 在个人澳洲VM内加入浏览器／图形使用能力，承接第一阶段的个人项目、身份与受控环境。具体网页用途和操作入口留到该阶段细化。 |
| 第三阶段：IDE | 在同一个人澳洲环境加入IDE与Claude Code集成，承接第二阶段的浏览器／图形能力及已有项目环境。产品和集成深度留到该阶段细化。 |

后续阶段继承员工本人VM的sudo及依赖／工具自主权、VM外网络隔离，以及Claude运行、实际授权浏览器和相关请求的澳洲VM／出口要求。受管双会话SSH／SFTP仍按设备身份映射到固定本人VM；新增浏览器或IDE不能自动开放员工直连客机SSH或扩大公司入口权限。自定义加密／终端中继全面防护及对抗sudo的令牌来源绑定不属于当前承诺，后续功能也不自动重新引入这些保证。

来源路线图中的协议、产品、参数、具体实现和验收举例均保留为候选，不提升为本阶段或未来阶段的已接受要求。各后续阶段实施前再细化相应规格；第一阶段首次OAuth授权仍受当前Q-2约束，不能由后续浏览器计划替代。
