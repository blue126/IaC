# 身份、访问与隔离 / Identity and access

## 公司边界与控制责任

公司提供个人VM、基础Claude Code、受管堡垒入口和网络隔离。员工拥有本人VM的sudo权限，自行安装、配置和升级依赖与工具；客机内的进程、配置和防火墙不作为防员工修改的安全边界。员工之间、家庭及PVE管理网的隔离由员工无权管理的VM外控制执行。

按用户确认的1A，个人VM可正常访问公网开发资源，受管路由经澳洲WAN出站；同时拒绝受保护目标及其公网回流路径。该保证不包含识别或阻止所有自建加密代理、终端／SFTP数据中继。禁用SSH内置转发仍是受管入口要求，但不能据此宣称任意应用层中继均已阻断。[OpenSSH转发说明](https://man.openbsd.org/sshd_config#AllowTcpForwarding)

公司提供的Claude运行及实际登录／同意浏览器会话仍位于澳洲VM，相关正常请求经澳洲出口。员工在公司环境外独立使用个人账号／令牌不纳入技术控制；本地浏览器完成公司授权仍不满足VM内授权要求。

## 受管接入与访问矩阵

员工设备先以独立设备身份登录堡垒服务，第一段SSH在受管入口终止；入口仅向登记的本人VM建立第二段SSH。员工不能指定其他目的地、获得堡垒通用shell或修改入口策略；SFTP同样只能到登记的本人VM。两段连接建立设备身份、员工与VM的关联，用于撤销受管会话。员工设备不直接SSH到客机；堡垒用户服务可部署在公司网关，但必须与管理员SSH／API等管理面分离。

| 来源 → 目标 | 结果 |
|---|---|
| 员工设备 → 受管堡垒用户服务 | 按登记设备身份认证，仅开放所选接入协议及明确的用户服务 |
| 受管堡垒 → 本人VM SSH／SFTP | 仅由服务端映射选择固定目标；禁用受管入口的SSH内置转发 |
| 员工设备 → 个人VM直接SSH／SFTP | 拒绝，不能绕过堡垒；公网不开放个人VM直接入站端口 |
| 员工设备 → 他人设备／VM／接入分配地址（若有） | 拒绝 |
| 员工VM → 他人VM／员工接入分配地址（若有，含本人客户端） | 拒绝主动连接；合法受管会话返回按连接状态放行 |
| 员工设备及VM → 家庭、个人Tailscale、PVE管理网 | 拒绝，含公网地址经NAT回流／转发到内部目标 |
| 员工VM → 公网开发依赖、Git、Claude | 正常公网开发访问，经受管澳洲WAN路由；受保护目标及其回流路径除外 |
| 员工设备及VM → 公司网关／堡垒管理面 | 拒绝管理员SSH／管理API等；协议必需入口、受限用户服务和明确基础服务按例外放行 |
| 管理员 → 公司接入设施及VM | 仅显式维护来源 |
| 员工环境 → 内部共享服务 | 无放行项，未来独立环境另定 |

客户端改路由、员工在VM内使用sudo修改网络或伪装地址不能增加对受保护资源的访问权限。覆盖同节点二层和IPv4／IPv6；实际部署跨节点时覆盖对应路径，未提供的IPv6路径阻断。家庭`.1`与公司下一跳设施的转发权限不等于本机服务访问；DNS等基础服务例外必须明确。受保护目标按最终目的地和服务识别，不能只排除私网CIDR。

## 个人OAuth与授权

员工以本人订阅登录。Q-2比较原生交互式OAuth与原草案setup-token候选；后者也需浏览器授权，并非免浏览器登录方案，不预定环境变量为唯一机制。[官方认证说明](https://code.claude.com/docs/en/authentication)

浏览器登录／同意会话必须在澳洲VM内，员工本人操作，管理员不代登录或手工转交令牌。仅在VM启动CLI、再在员工本地浏览器打开URL，即使使用代理也不满足要求。第一阶段保持终端操作；先验证VM内终端浏览器能否完成真实流程。任何一次性图形入口仍须用户批准范围变更，不默认开放VNC／RDP、PVE控制台或认证门户。

按用户确认的2A，验收采用实际VM内授权流程、本人身份和澳洲出口的过程证据。A-4的防sudo替换／密码学来源绑定推定已退役，不实现额外绑定组件，也不宣称员工无法替换凭据或客户端。首次登录及到期／撤销后的重新登录均按Q-2核对实际流程、认证来源和正常请求路径；检查其他API key／认证变量是否抢占本人订阅，但不把此检查解释为持续防篡改保证。

个人凭据由员工管理。Linux原生登录文件权限等基础保密措施不意味着管理员或拥有sudo的员工技术上无法读取；个人令牌不默认集中托管、不代发、不新增自动续期。浏览器登录态／会话与令牌同属个人凭据，其持久配置及VM快照／备份副本的许可、技术可读者、访问和留存由Q-6在首次配置凭据前确定。

令牌、SSH及设备私钥不进入Git、Terraform输入/state、Cloud-Init、模板、命令历史、普通日志或管理员排错材料；验证只报告存在性，不输出秘密值。SSH公钥与设备接入身份分别管理；采用设备密钥的协议时私钥留在所属设备，系统部署凭据遵循采用的Vault架构。

## 登记、停用与保留盘

1. 分配本人VM及sudo权限，登记设备身份、员工／VM映射和两段SSH授权；员工自主管理工具、开发、测试和交付。
2. 设备撤销使该设备的公司受管身份、规则和关联的两段既有会话失效，其他获准设备仍可用；保证范围不包含员工自建第三方通道或整个VM。
3. 员工停用撤销全部公司身份、映射及SSH授权，并从VM外断网或停机，终止该VM的访问和既有外连通道；保留磁盘，不自动删除数据。
4. 保留盘按可能含有效个人凭据的敏感资产限制访问。Q-6确定副本处理、交付和读取权限前，不向新员工复用或向无关人员交付，也不默认挂载读取凭据目录。清理或删除仍需具体授权。
5. 删除副本不等于撤销已签发令牌；外部个人令牌撤销不是公司停用的技术前提。验收记录保留盘的访问限制与副本处理状态，不声称已清除或已撤销。

排错仅用所选协议连接状态、必要日志、VM状态和反馈，不收集请求正文或秘密值，不新增集中运维平台。
