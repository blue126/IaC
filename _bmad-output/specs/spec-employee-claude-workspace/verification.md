# 试用与验收 / Verification

## 已有证据与线路试测

用户已于2026-10-20确认澳洲侧浏览器与直接terminal正常，不重复列为未做事项。员工网页终端及cloudflared原生SSH均反馈高延迟；无量化RTT／丢包和明确WARP／VLESS结果，根因未定。

线路测量是可选参考。比较路径时使用相同员工、网络、测量方法和明确归属端点；旧入口或不同方法的数据不直接排名，合成测量不替代真实工作验收。原A-5中Q-8前禁止员工代码／OAuth的预筛安排不再作为强制前置；首次配置凭据仍须满足Q-2／Q-6，任何网络或部署变更仍须获得相应授权。

## 验收矩阵

| 项 | 通过证据 |
|---|---|
| CAP-1 工作交付 | 员工拥有本人VM的sudo，自行安装／配置项目依赖与工具，完成真实项目修改、检查／测试及Git／文件交付；再次进入仍有项目与配置（A-1） |
| CAP-2 订阅与凭据 | 核实本人订阅资格和实际认证／模型请求，无其他认证来源抢占；对获准材料检查Git、Terraform输入/state、Cloud-Init、模板、另一VM、命令历史、普通日志及排错材料无员工令牌／私钥／浏览器会话秘密。持久登录态及快照／备份符合Q-6许可、访问与留存；只报告存在性，不输出秘密值 |
| CAP-3 受管入口 | 登记设备经堡垒用户服务到固定本人VM的两段SSH可用，SFTP仅到同一固定目标；未登记／已撤销身份、指定其他目标、堡垒通用shell和受管入口SSH内置转发均拒绝。员工设备直连客机SSH／SFTP与公网直达客机均拒绝 |
| CAP-3 本人及设备隔离 | 他人设备／VM／接入分配地址（若有）不可达；修改客户端路由、以sudo修改VM网络或伪装地址不增加权限。同节点二层覆盖；实际部署跨节点时验证对应路径，单节点不宣称已验证跨节点 |
| CAP-3 受保护目标 | 家庭、个人Tailscale、PVE管理网、CN Proxy、家庭／公司网关及堡垒管理面拒绝；测试公网回流到内部服务及网关本机管理／代理／DNS。协议必需入口、受限堡垒用户服务与明确基础服务正常，不能以全部阻断掩盖未实现的服务分离 |
| CAP-3 IP路径 | 检查IPv4／IPv6及DNS例外。对明确归属且获准的家庭公网地址／受保护服务做回流测试，结合规则／日志或管理侧正向对照判断；证据不足记未验证，不以目标服务停机代替隔离证据 |
| CAP-4 授权流程 | 员工实际在澳洲VM内完成浏览器登录／同意，记录流程、本人身份及澳洲请求出口的过程证据；本地浏览器完成授权不通过。不要求或宣称防sudo替换的令牌来源绑定，A-4已退役 |
| CAP-4 受管出口 | 受管默认路由和正常Claude请求经澳洲WAN；员工修改客机路由／地址不能打开对受保护资源的路径。正常公网开发访问可用；不把本项通过解释为能识别／阻止所有自定义加密代理、终端或SFTP中继 |
| CAP-5 试用 | 固定员工、网络与明确归属目标，记录回显／卡顿、RTT／抖动／丢包、掉线及原生重连，完成真实任务。可顺序切换线路并记录配置；正式保留入口须通过当前CAP-3／4，历史参考数据不替代验收 |
| CAP-5 扩展 | 每位新员工上线前核对其节点／网络的CAP-2身份与凭据、CAP-3隔离、CAP-4实际授权／受管出口及CAP-6设备映射；按Q-3确认的实际并发完成真实任务，员工与负责人确认可用，不虚设数值阈值 |
| CAP-6 设备撤销 | 指定设备的公司受管身份、规则和关联的两段既有SSH／SFTP会话失效，其他获准设备仍可用；不据此声称第三方自建通道或整个VM已停用 |
| CAP-6 员工停用 | 分别证明全部公司身份／映射／SSH授权失效，以及VM外断网／停机终止该VM访问和预先存在的获准测试通道；磁盘保留，记录Q-6副本处理及访问限制，不以外部个人令牌撤销为前提 |
| 既有公司入口 | 正式上线前核对旧试用VM、Access应用／路由与连接器；仍存续的公司提供入口按范围下线，或纳入当前受管堡垒、隔离和出口约束。未知状态不判通过，不以新入口通过代替旧入口处置 |
| 既有业务 | 家庭WAN／DNS／DHCP、qnetd、个人代理及管理员维护仍正常 |

以上CAP-3检查覆盖公司受管入口和直接网络可达性，不要求识别／阻止所有员工自建反向隧道或数据中继。客户端断线仅观察接入／网络原生重连，不增加独立会话恢复或VM故障后进程续跑要求。所有功能证据仍待实际执行，文档自检不能替代实测。

## 通过判定

强制项须有可重现的配置、身份、路径和结果证据；未执行／未核实不等于通过。未部署的跨节点路径可注明不适用及原因；拒绝项须有可区分策略拒绝的正向对照或规则／日志证据。

CAP-4按用户确认的1A／2A判定：实际VM内授权及身份核对完成，正常Claude请求经澳洲出口，受管路由与外部隔离按矩阵生效。不再要求“无任何可用应用层中继”或“员工不能替换实际凭据”；受管SSH转发拒绝和网络拒绝目标仍须分别通过，不能用范围调整免除这些检查。

Q-2按员工真实登录方式检查登录、同意、回调、邮件链接／SSO／二次验证等适用环节；区分离线因子读取／输入与实际在线授权请求。终端浏览器是否能完成该账号流程须实测；若无法满足VM浏览器／澳洲请求条件，记录失败并交用户决定，不能自行改为本地浏览器或增加图形入口。

## 决定与实施时序

| 项 | 必须解决的时点 |
|---|---|
| Q-1 接入选择 | 受管堡垒两段SSH／固定目标SFTP已定；正式接入线路在实际工作验证后确定。可选预筛不依赖原A-5，对照结果不自动改变自建要求 |
| Q-2 授权入口 | 首次及重新登录前按VM内浏览器标准核实实际终端授权路径、本人订阅和正常请求出口；不新增令牌来源绑定。若必须图形入口，先取得范围变更批准 |
| Q-3 身份／项目／并发 | 交付前核实订阅，试用与扩展前确定项目、系统和实际并发 |
| Q-4 网络策略 | 配置前核实PVE后端／启用层级、网桥／VLAN／交换能力；明确受保护目标、公网回流、DNS、维护来源及正常公网开发出站规则 |
| Q-5 家庭及旧公司入口 | 配置前核对入站／回流、地址／域名、Access应用和连接器；正式上线前确定旧入口关闭或纳管并验证，不影响共用业务 |
| Q-6 留存数据／凭据 | 首次配置凭据前确定个人凭据、浏览器会话及快照／备份副本的许可、技术可读者、访问与留存；读取、交付、清理或删除保留盘前明确授权，不自动删除或复用 |
| Q-8 控制边界 | 按1A／2A执行VM外网络隔离、受管堡垒及过程验收；原全面应用层防绕行和A-4来源绑定不再构成实施前置，不推导收回员工sudo或工具自主权 |
