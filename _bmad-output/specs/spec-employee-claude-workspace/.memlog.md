- (capability) CAP-1：员工使用个人终端开发环境管理项目和依赖；成功为可登录本人 VM、自主管理开发工具、完成真实修改和项目检查，并以 Git 或 SSH 文件传输交付。
- (capability) CAP-2：员工在无日常浏览器的目标环境使用自己的订阅身份；成功为个人 OAuth 令牌认证并完成一次模型请求，身份与计费来源可确认且凭据不与其他员工共享。
- (capability) CAP-3：员工只访问自己的工作资源；成功为本人终端可用，他人设备、VM、个人 Tailscale、家庭及 PVE 管理网不可访问，改客户端路由或本人 VM 配置也不能扩大权限。
- (capability) CAP-4：Claude 相关访问由澳洲 VM 经澳洲出口发起；成功为首次授权和模型请求均有符合要求的发起位置与网络路径证据，IPv4/IPv6及代理配置不产生旁路。
- (capability) CAP-5：从员工所在地稳定完成日常工作并逐步覆盖5–10人；成功为真实时段试用完成任务，记录交互、网络和原生重连表现，通过员工与负责人确认后扩展并检查并发与上行负载。
- (capability) CAP-6：管理员按人员和设备管理接入；成功为登记设备身份及本人 VM 映射，撤销一个设备或员工的访问时不需更换其他人的密钥，VM数据处置遵循另行确定的保留安排。
- (constraint) 第一阶段纯终端、个人订阅 OAuth；第二阶段浏览器、第三阶段 IDE。首次令牌授权仍须满足澳洲 VM/澳洲出口，尚未确认如何提供该授权入口。
- (constraint) 公司接入自建维护，独立于个人 Tailscale；稳定性优先。员工有本人 VM 管理员权限，隔离必须在其不可修改的网关/PVE网络层执行。
- (constraint) 默认只允许员工设备到本人 VM 的 SSH TCP22及必要返回流量；公网开发依赖、Git、Claude经澳洲出口；员工网络无内部共享服务放行项，无公网直连VM入口。
- (constraint) 隔离覆盖IPv4、IPv6、同节点二层及跨节点路径；若不提供员工IPv6，其路径不放行。管理员维护来源须明确，客户端路由和客户机防火墙不能独立构成隔离。
- (constraint) 个人OAuth令牌、SSH私钥和设备私钥在分配后配置，不进入模板、Git、Terraform参数/state、Cloud-Init、共享日志、命令历史或交给管理员的排错材料；系统部署凭据沿用仓库Vault。
- (constraint) 保留既有家庭WAN、DNS/DHCP、管理连接、qnetd和个人代理业务；新资源地址、VMID、网段、VLAN先对账再分配，不默认现有桥或规则可复用。
- (constraint) 沿用Terraform负责VM基础设施、Ansible负责主机配置的分工；仅补隔离所需最小模块参数，不因规格产生部署或安装授权。
- (decision) Non-goals：本阶段不提供日常浏览器/IDE，不采购或切Team，不切API计费，不建设共享内部服务、监控/集中日志平台、认证门户、令牌代发/自动续期或额外恢复/保活/HA。
