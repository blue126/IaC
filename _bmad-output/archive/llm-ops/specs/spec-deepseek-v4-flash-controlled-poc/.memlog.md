- (decision) 规格 slug 为 deepseek-v4-flash-controlled-poc，覆盖 Phase 0–5 的完整受控 PoC 合同。
- (decision) 当前下游实施授权仅限 Phase 0 离线 IaC；Phase 1–5 是合同化后续阶段，不因本规格生成而获得执行授权。
- (capability) CAP-1：系统提供独立的 DeepSeek V4 离线 IaC 路径，包含专用 role/playbook、Compose、生命周期 unit、release manifest、验收 fixture 与 benchmark harness；本地语法/渲染验证通过且不连接或改变 VM。
- (capability) CAP-2：未来生产 desired state 可移除 MiniMax 与 Qwen，并阻止旧 role/handler 在后续部署中重新下载或启动它们；GLM 配置与权重保留为停止状态的冷回滚。
- (capability) CAP-3：经明确授权开机后，操作者可运行非变更 preflight，完整采集驱动、CUDA、Docker/Toolkit、双 GPU、PCIe/P2P、CPU flags、guest/ESXi NUMA、磁盘/datastore 与现有 artifact 证据。
- (capability) CAP-4：系统支持受控 artifact 准备：先备份 Open WebUI 并验证 GLM 路径，再解析精确删除清单并另行获批，最后下载和校验固定 revision 的官方模型与固定 digest 的运行时镜像。
- (capability) CAP-5：系统可在停止所有旧推理后端后，以 KTransformers/SGLang-KT 的 TP1、单 RTX 3090、16K context、并发 1、MTP 关闭配置启动隔离 PoC，并只通过 loopback 或私有容器网络提供端点。
- (capability) CAP-6：验证工具可判定 OpenAI Chat Completions、SSE、reasoning 分离、单个/并行 tool calls、tool result continuation、畸形或截断 DSML 安全失败，以及 Open WebUI 端到端兼容性。
- (capability) CAP-7：基准与验证工具可记录正确性、TTFT、prefill/decode、RSS、swap、每卡 VRAM、NUMA/ESXi 计数器、冷启动、清洁重启、首次长 prefill 与一小时 soak，并据固定阈值作出通过或停止决定。
- (capability) CAP-8：TP2、并发 2、更长 context、量化 cache、GPU expert 调整与 MTP/DSpark 均可作为单变量实验独立晋级；TP2 仅在正确性一致、稳定且用户体验或吞吐约提升 10% 时晋级。
- (capability) CAP-9：系统支持门控生产切换与可演练回滚；只有完整合同通过后 DeepSeek 才能成为唯一 boot backend，失败时停止 DeepSeek、恢复 Open WebUI 连接并启动保留的 GLM。
- (capability) CAP-10：每个候选发布生成可审计 manifest，记录模型仓库和完整 revision、镜像 digest、运行时/引擎 commit、驱动与 CUDA、GPU ordinal、全部参数、拓扑、fixture 版本及测试结果。
- (capability) CAP-11：系统生成操作与恢复证据，使操作者能复现部署、识别进程健康但输出错误、执行冷恢复与 GLM 回滚，并在真实部署后形成中文 learning note，明确区分预测与实测。
- (constraint) 复用现有 ESXi llm-server VM：36 vCPU、340 GiB 全预留 guest RAM、600 GB thin VMDK、EFI、64-bit MMIO、两张手工 DirectPath RTX 3090；不新建第二台 VM。
- (constraint) 两张 24 GB RTX 3090 不构成透明 48 GB 地址空间，且 SM86 无原生 FP8/FP4 Tensor Core 路径；首选方案必须是 CPU/RAM 承载 MoE 专家、GPU 加速其余算子的异构推理。
- (constraint) 首选 artifact 是 deepseek-ai/DeepSeek-V4-Flash-0731 官方 safetensors，首选运行时是 KTransformers/SGLang-KT；现有 ik_llama.cpp f7923739 不支持 V4，不得原地升级覆盖。
- (constraint) 同一时刻只允许一个大模型后端拥有主要 RAM/GPU；生命周期层必须强制 DeepSeek 与 legacy backend 互斥，不能依赖人工惯例。
- (constraint) Terraform 只拥有 VM 硬件，Ansible 拥有 guest 配置与期望状态，Compose 拥有容器图，systemd 拥有开机编排与显式启停；禁止 ad-hoc 容器、直接 shell 下载和竞争性 restart owner。
- (constraint) 模型 revision、镜像 digest、运行参数、parser 配置与 fixture 必须作为同一兼容发布集固定和晋级；禁止生产跟随 main 或 latest。
- (constraint) 模型卷只读、容器不得 privileged、仅授予已证明必要的 GPU 与 SYS_NICE/IPC 权限；推理 API 默认不匿名暴露到 LAN，凭据仅通过 Ansible Vault 间接注入。
- (constraint) Phase 0 只能修改本地仓库并本地验证，不能访问 VM、ESXi 或外部运行态，不能下载模型、拉取镜像、删除 artifact、停止服务或切换生产。
- (constraint) Phase 1 开机与 preflight、Phase 2 删除/下载、Phase 3 停旧服务并启动 PoC、Phase 5 生产切换均是独立运行时审批门；删除审批必须基于已解析的精确目标列表。
- (constraint) 模型下载前必须证明约 400 GB 实际可用模型存储余量或采用独立模型盘，并同时核对 guest filesystem、thin VMDK allocation 与 datastore headroom。
- (constraint) TP1 黄金基线固定为单卡、16K context、并发 1、MTP 关闭和保守 cache；任何优化一次只改变一个主变量。
- (constraint) 最低生产门包括固定 corpus 零乱码/空答/静默结构错误、median decode 至少 8 tok/s、无持续 swap/OOM、完整 API 合同、冷启动/重启/长 prefill/一小时 soak 与回滚演练全部通过。
- (constraint) Ansible 遵循专用 kebab-case role/playbook、英文动词任务名、service 前缀 snake_case 变量、Deploy + Verify 双 play、幂等与窄标签执行；依赖在 playbook 显式排序。
- (decision) 若 KTransformers 正确但低于性能门，才按同一 corpus 顺序评估独立安装的当前 ik_llama.cpp Q4 CPU-MoE；若两条路线均失败则停止投入并记录为可加载但不可服务。
- (decision) PoC 不采购新 GPU；只有 Phase 1 证据显示存储不足时才评估独立 SSD/VMDK。
- (direction) 非目标：不承诺全 GPU、1M context、高并发或生产级横向扩展；不引入 Kubernetes、service mesh、消息总线、API gateway 或完整 Prometheus/Grafana。
- (direction) 非目标：本轮不删除 MiniMax/Qwen/GLM 文件、不启动 VM、不下载模型或镜像、不修改 ESXi 拓扑、不生产切换，也不把现有 Open WebUI 数据库迁移当作 Phase 0 的附带重构。
- (assumption) 用户对拟定边界的确认包含 Phase 0 本地 desired-state 变更：MiniMax/Qwen 可从未来生产 inventory/boot 选择中移除，但远端文件保持不变。
