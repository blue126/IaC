# 个人 Claude 授权入口：Browsh 实测失败后的调整提案

状态：用户于 2026-10-22 以“你赶紧改吧”批准本提案范围，已部署至网关和两台员工 VM，匿名图形输入／隔离／撤销已验证；本人 OAuth UAT 待完成。

## 已确认的问题

用户截图出现正文空白、无法输入。control VM 的空白配置复现确认：Browsh 地址栏能够收到不提交的测试文字，但登录正文发生错位、混入隐藏导航，翻页会变空白，未验证到邮箱框可实际输入。普通滚动、Tab、单色、文本可见性及临时布局对照均未形成可靠的可交付操作。

独立原生 Firefox 在同一公开登录页有可见邮箱输入框和正常按钮，已保存匿名截图。没有输入个人账号或提交表单，没有读取或修改 pilot 正在使用的浏览器会话。

Browsh 右下角 Unsupported version 来自官方 v1.8.2 的 overlayCallToSupport 捐助提示，并非版本检测错误。不能据此盲目升级或认为付款可以解决兼容问题。

先前原生连通检查仅匹配标题/文字中的 sign in/continue/email，证明了 URL 交付和页面加载，不能证明登录表单可操作。该过强结论已撤回；本人 OAuth 从未标为通过。

## 建议的最小范围变更

仅在本人首次/重新授权期间提供图形 Firefox 窗口，浏览器进程与 Claude CLI 都仍在澳洲个人 VM；本机浏览器只显示远端画面和传递本人输入，不直接打开个人 OAuth 地址。

| 对象 | 拟定行为 |
| --- | --- |
| 员工 VM | 使用现有原生 Firefox，增加虚拟显示和受控图形查看所需组件；以 employee 身份运行，不用 root 登录个人账号 |
| 受管网关 | 增加一个仅绑定现有 WireGuard 私网地址的授权查看入口，候选端口 8443；只接受登记设备经 wg 接口的请求 |
| 身份与目标 | 复用登记 WireGuard 设备身份及固定设备到 VM 映射；客户端参数不能选择任意目标、端口或代理 |
| 本机 | Agent/员工打开私网查看地址；个人邮件、SSO、验证码及同意由本人操作 |
| workspace-login | 启动官方 CLI 与 VM 内图形浏览器，提供私网查看入口，成功后检查本人订阅认证来源 |
| 结束 | 关闭本次图形查看会话/临时监听；已有 VM 登录态按此前确认的默认持久行为保留，不清除个人凭据 |

图形查看使用已加密、预核验对端的现有 WireGuard 连接；不新增公网入站映射，不对家庭 LAN 或公网开放 VNC/RDP，不开启 SSH forwarding/ProxyJump，也不授予直连其他 VM 的能力。网关新增入口、设备限制、固定映射和撤销行为需要在代码与真实环境验证后才能交付。

具体图形组件应先在 control VM 无个人账号验证可见邮箱框、实际测试文字输入、正常/取消退出和访问隔离；通过后再部署到员工 VM。新增组件安装与这项图形授权例外已获用户明确批准。

## 必须验证的条件

1. 原生授权页实际可见、本人能用键盘输入、按钮可操作。使用不提交的测试文字，不用真实邮箱验证机械输入。
2. 正常完成与取消后，图形入口按预期关闭；CLI 登录结果来自实际认证状态。
3. 未登记/撤销设备不能新建或继续访问；另一员工不能访问此 VM。
4. 无公网或 LAN 新监听；只有指定 WireGuard 接口和设备可用。
5. 现有 SSH/SFTP、VM 外隔离、停用保盘仍有效。
6. 实际账号授权、邮件/SSO/二次验证及真实项目仍由本人 UAT，不能由匿名 UI 检查替代。
