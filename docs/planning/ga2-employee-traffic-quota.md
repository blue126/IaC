# GA2 员工月度接入流量配额：业务约束

2026-10-29 审核修订：本文件仅约束与现有员工接入平行建设的 [OCI 员工 VPN Hub-and-Spoke](../architecture/oci-employee-vpn-hub.md)，profile 为 `oci-hub`。现有方案继续运行；不迁移用户、不关闭入口、不退役 VM500。新方案独立分配 VM/VNet/设备凭据与 overlay，由 PVE 纯路由和网络级隔离、OpenWrt 新方案聚合回程提供出网；OCI 负责 VPN 身份、访问控制和本方案月额度。

## 用户已确认

- 新方案内每用户（员工）每月独立 5 GB，上传＋下载合计；不同用户不共享，同用户的新方案设备归集。现有方案流量和访问资格不纳入本月账。
- 仅计算员工设备与工作区之间的 SSH、文件传输与桌面等受管接入流量。
- VM 内访问 npm、Git、Claude API 等公网开发服务不计入。
- 接受轮询造成的小额超用；检测超额后停用该用户全部新方案设备，停止已有受管接入并拒绝重连，次月自动恢复额度资格。
- 第一版采用 WG Portal 管用户/设备，小型任务定时记账和调用 API，SQLite 持久化；不采用 nftables 内核硬额度。
- 月重置不能恢复管理员停用或已撤销设备；员工 VM sudo 不能改动 OCI 配额和外部隔离。

## 设计执行边界

OCI 定时任务以 5 秒作为试点采样间隔，读取新方案员工接口 `wg-users` 的登记设备 peer RX/TX：RX 是员工上传（电脑→OCI→VM），TX 是员工下载（VM→OCI→电脑）。累计增量按用户归入 SQLite 月账，向 OCI 命令执行器提交停用动作，由执行器持锁调用 Portal API 停用该用户全部新方案设备；不操作现有方案设备或 VM Spoke，不把工作区接口同一流量再次相加，不给新增设备单独赠送额度。

采用 VPN peer 报告字节，不能称为文件净大小、严格内层 IP 有效流量或腾讯计费量。采样基线、周期、用量和停用原因持久化；接口计数回退不扣减已用量。普通意外重启恢复已提交月账并记录未采样缺口，账本损坏或归属无法确认时暂停受影响用户。

WG Portal 不是原生月配额产品；小型组件补齐月账、判断和自然月恢复。Portal 是新方案 OCI 端指定接口及 peer 的唯一配置/恢复写入者，不与 Ansible 模板或 wg-quick 服务同时管理同一接口；VM Spoke 仍由 Ansible 管理。关闭自动导入、自动批量恢复和自动创建设备。开户/撤销、人工停用、采样任务和月恢复统一经 OCI 命令执行器串行操作，只有执行器持 Portal 写 API 凭据；管理员本机不直接写 Portal，人工面板写操作先进入维护模式。

SQLite 保存用户/设备/工作区各自的多原因集合，Portal DisabledReason 只是显示摘要。即使已经因超额停用，管理员再次停用也必须增加 admin_disabled；月切换只清除旧周期 quota 原因，锁内核对映射/有效期和所有原因后才恢复。action_id 和待执行记录用于 API/数据库中断恢复。

私有管理员工程保留统一入口，负责用户—VM—Portal 对象关联、BWS、开户、bundle 和 Temp.sh/邮件交付；配额任务源码归该工程，由 Ansible 受控部署到 OCI 常驻运行。唯一运行月账在 OCI，管理员电脑关机仍须正常记账和月恢复。本地台账以 `(profile, employee_id/device_id)` 保存 Portal 用户 ID、peer 公钥、VM overlay 和 BWS 独立记录关联；新方案不另写一份 Hub peer 配置，现有后端和已发包保持。完整流程和重试契约见架构方案第 10 节。

新方案采用独立 BWS 项目和专用机器账号，现有 EmployeeWorkspace 及其加载器保持；先预检项目绑定再写记录。部署端仅把单一 Portal API 凭据等必需值交付 OCI，OCI 不持有任一 BWS 项目令牌。PVE 新工作区 pre-start 及 OCI Portal 恢复必须等待实际隔离规则就绪；规则检查失败拒绝启动。新 Terraform schema/资源键独立，通用 VM module 先补齐 hook、首次停止创建和新工作区删除保护。

开户/撤销须将明确代次的用户—设备—VM 映射及策略发布到 OCI；运行任务使用 OCI 本地清单，不远程依赖管理员电脑。接口计数重建时补记新代次首样本，月切换保留采样基线，避免漏计或重复计入整个历史累计。

GA2 的未认证流量、握手及外层开销仍可能收费，员工额度不能保证云费用绝对封顶；必须另配总带宽、预算告警和可验证的紧急停用流程。

## 实施前展示确认与验收

已确认：5 GB=5,000,000,000 字节，Asia/Shanghai 自然月每月一日重置，首版 5 秒采样；长停采跨月无法拆分时仅暂停受影响账户待核对，不自动整段归新月或按零恢复。验收记录采样间隔、超用量和 API 停用生效时间；不承诺字节精确硬截止或所有空闲 socket 瞬时关闭。次月只恢复因超额停用且仍有效的设备；保留管理员封禁、撤销和工作区维护状态。

先完成独立项目/模块默认兼容预检、原因叠加和并发状态原型，再使用新建测试 VM 验证启动门控和两用户/多设备的双向记账、持续 WSS/SSH/SFTP 停用、月恢复及故障处理。quota 后人工停用的设备次月仍保持停用；原型通过后才向实际申请用户交付。独立网络/身份不授权到现有工作区，不依赖关闭现有入口来达成新方案配额。

管理员集成另验中断重跑的用户/设备唯一性、方案内重试复用密钥、跨方案凭据独立、Portal 与台账归属一致、先验证后交付，以及管理员电脑离线时 OCI 仍执行配额；online 区分两方案，未知状态不能当作无人在线；现有查询和开户默认路径继续保留。

当前仅完成平行建设设计，未部署、未启用配额；本范围不包含现有方案迁移、VM500 退役或现有入口关闭。


原型代码与精确运行契约现见 [OCI Hub 原型 runbook](../deployment/oci-hub-workspace-prototype.md)。合成 SQLite/HTTP/namespace 验证与真实部署验收分别记录；实际用户月额度、Portal 恢复和真实 GA2/WSS/SSH 截止仍需上线门槛验证。
