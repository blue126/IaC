# VM509 独立 OCI Hub 端到端延迟测试

完成时间：2026-10-30T16:00:39+11:00。

路径：中国海南电信测试路由器 192.168.8.1（公网 61.186.5.82）→ 普通公网 WireGuard → OCI 159.13.46.201 → VM509 自有 WireGuard Spoke。未使用 GA2。VM509 物理出口为 10.236.1.2 → PVE 10.236.1.1 → OpenWrt；未经过 VM500 或旧站点隧道。

计时在中国主机本地使用 nixio.gettimeofday 完成，管理 SSH 往返不计入；每轮每协议30次，共两轮。UDP 为到 VM509 overlay:60049 的有效回显，TCP 为到 VM509 SSH端口22的新连接建立时间，不是SSH认证/命令回显或实际Mosh会话体验。先预热5次。

分位数只计算成功样本；失败另列。两轮UDP合计4/60（6.67%）没有有效回显，成功样本中位数335.295ms、P95 387.091ms。TCP 60次均建立连接，但最大1371.540ms，第二轮P95 1335.840ms；连接成功不代表底层没有丢包。

结论：独立 Hub-and-Spoke 数据路径已跑通，稳态网络RTT约336ms；长尾和UDP可靠性仍不理想。中国→OCI TCP对照中位数326.940ms，本轮大部分往返时延已出现在跨境段，但不能把两种协议的差值直接归为Hub处理开销。没有本轮同设备、同协议到同VM的旧直连对照，不用历史不同设备/协议数据计算提速百分比。

实际路径证据：OCI观察到客户端端点61.186.5.82、工作区端点114.76.119.2；客户端目标VM路由走wg-rtt509；VM到OCI路由走eth0，经10.236.1.1，源10.236.1.2。测试前后中国测试机到OCI均走pppoe-wan。未切换现有代理/VPN设置，测试接口仅增加两条精确/32路由。

测试前修复两项部署问题：克隆保留模板主机名；OCI原有FORWARD末尾REJECT拦截新WG接口。兼容规则从原Hub设备/VM/端口映射派生，未更改既有Docker/Tailscale规则和默认策略。新增隔离内核回归覆盖拒绝复现、精确TCP/UDP放行、错误源/目标/端口拒绝、撤销和外部规则保留。
