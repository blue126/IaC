# GA2 香港入口回源 OCI：计费与流量方向

核对日期：2026-10-28。范围：香港普通 BGP 接入、香港终端节点组、公网回源悉尼 OCI。按人民币刊例价及测试账号账单核对；不涉及创建或修改云资源。

## 1. 上传和下载以员工电脑为准

```text
上传 U：员工电脑 → 香港 GA2 → 悉尼 OCI → 工作区 VM
下载 D：员工电脑 ← 香港 GA2 ← 悉尼 OCI ← 工作区 VM
```

在 OCI 的员工 WireGuard 接口读取某个员工设备 peer 时，RX 是员工上传，TX 是员工下载。不要将 OCI 的工作区接口同一包再次相加；该接口的收发方向也与员工接口不同。VM 自身下载 npm/Git/Claude 等开发公网流量不属于员工接入流量。

## 3. 费用怎么算

公网和传输项采用主流量口径；CU 当前按处理的上下行流量合计计费。简化测算在每个小时 h，令上传为 U_h GB、下载为 D_h GB，三个网络计费段的主流量近似一致为 M_h = max(U_h, D_h)，则：

```text
接入公网费 = 0.700 × M_h
回源公网费 = 0.700 × M_h
传输流量费 = 0.525 × M_h
CU 处理费  = 0.386 × (U_h + D_h)

该小时估算 = 1.925 × max(U_h, D_h) + 0.386 × (U_h + D_h)
月估算 = 各小时估算之和
```

严格按账单分别取接入、回源、传输的各自计费用量，而非强制令其相等；实际测试账单这三者存在差异。以上简式用于相同业务量、忽略协议和统计差异的预算估算。月主流量不能直接用整月总上传和总下载取一次最大值来替代按小时归集；多个员工还会在实例/地域计费维度聚合，不是每人独立出腾讯账单。

同一小时上传 1 GB、下载 4 GB 的例子：

| 收费项 | 算式 | 金额 |
| --- | --- | --- |
| 接入公网费 | 4 × 0.700 | 2.80 元 |
| 回源公网费 | 4 × 0.700 | 2.80 元 |
| 传输流量费 | 4 × 0.525 | 2.10 元 |
| CU 处理费 | (1 + 4) × 0.386 | 1.93 元 |
| 合计 | | **9.63 元** |

U/D 在此应视为 GA2 处理的网络流量，而非文件净大小。WireGuard 外层、握手、keepalive、协议重传及未知来源流量会造成员工配额计数与 GA2 账单差异；OCI→家中的第二段隧道没有再次穿过 GA2，不额外重复计入 GA2。OCI 自身云服务费用及员工家庭/运营商费用不包含在表内。

## 4. Q&A

- 去到 OCI 是上传吗？从员工电脑出发经 GA2 去 OCI 是上传；OCI 向员工电脑返回是下载。
- OCI 从家中 VM 收到的数据算什么？只有经员工接口发回员工的数据属于这里的下载，不能把工作区侧接收再计一次。
- 香港到香港为什么收费？本账号实际账单明确收取该传输项，名称是供应商账单分类；同地域不代表该项自动免费，不能再用地理直觉消去费用。
- 每用户 5 GB 是单向还是双向？是新建 `oci-hub` 方案内每用户每自然月上传＋下载合计 5 GB；同用户的新方案设备归集，不同用户额度独立。现有员工方案独立运行，不纳入本月账。例如本方案内上传 1 GB、下载 4 GB 就触额，不是两个方向各 5 GB。
- 每用户额度等于腾讯账单吗？不等于。用户额度用 OCI 员工接口的设备 peer RX＋TX 记账，接受轮询期间少量超用；腾讯按各计费维度、处理流量和协议开销收费。产品额度不采用 GA2 主流量的 max(上传, 下载) 口径。
