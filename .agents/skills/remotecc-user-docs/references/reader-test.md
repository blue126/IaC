# 读者测试

思路来自 Anthropic `doc-coauthoring` skill 的第三阶段：作者带着上下文，看不出文档缺了什么，所以让一个没有上下文的读者来读。

## 步骤

1. **预测问题**：针对这一页，列出 5–8 个真实员工会问的问题。至少包括：一个顺利路径问题、一个出错时怎么办的问题、一个关于数值或时限的问题。
2. **找无上下文读者**：有子代理时，启动一个新的子代理，只给它本页正文、读者画像和问题清单，不给仓库、代码或本次对话。没有子代理时，请用户在新会话中粘贴同样的材料。
3. **读者画像**：
   > 你是一名刚拿到 RemoteCC 工作区的员工，会基本的 Linux 命令，不了解 WireGuard、Cloudflare 或公司内部系统。只根据下面这一页回答问题；页面没写的，回答“页面没说”，不要猜。最后列出你读的时候哪里不确定、哪里可能做错。
4. **判定**：
   - 回答“页面没说”的问题，判断它是否属于本页职责：属于就补，不属于就加链接。
   - 读者的回答与事实来源不一致的，说明有歧义，改写原句。
   - 读者列出的“可能做错”的步骤，补成功标志或前置警告。
5. **复测**：修改后用同样的问题再测一次，直到没有新的缺口。交付时附上问题清单和最终结果。
