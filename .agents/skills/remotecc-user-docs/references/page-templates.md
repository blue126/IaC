# 页面写法

按读者来看这一页时想做什么，分三种写法。一页只用一种；写着写着需要另一种内容时，拆开或链接过去。链接路径以 `remotecc/apply-site/docs/ARCHITECTURE.md` 为准。

## 首页与分组页（`_index.md`）

目标：让读者在十秒内找到该看哪一页。不写正文知识。

```markdown
---
title: 快速开始
description: 一句话：这里有什么、什么时候看
weight: 1
---

一两句：按什么情况看哪一组。
```

子页列表由 OINK 根据各页 `title` 和 `description` 自动生成，所以每页的 `description` 要写成一句完整的“这页解决什么问题”。

## 步骤页：带读者做成一件事

适用于按顺序完成的事，例如开通后的每一步、传文件、换设备。假定读者知道自己要什么，只走成功路径；分支情况一句话交代并链接出去。

```markdown
<一句话：做完这页你能做到什么，适用什么场景。>

开始之前，你需要：
- 前置条件

## 1. 动作
一到三句。动作在前，结果在后。
成功标志：你会看到……

## 2. ...

## 下一步
如何确认做成了，接下来看哪一页。
```

如果某一步常出错，在那一步后面写“如果看到……，见常见问题的对应条目”，不在开头堆警告。

## 说明页：讲清楚规则或数值

适用于规格、额度、时限和“为什么这样”的规则。不写操作步骤。

```markdown
<一两句：这页讲什么规则。>

| 项目 | 值 | 说明 |
| --- | --- | --- |
| 名称 | 值 | 一句话 |

## 这对你意味着什么
- 员工能感知的影响，以及对应该怎么做（链接到步骤页）
```

需要解释网络路径等原理时，用两三段文字加一张简图，结论落在“对你意味着什么”。

## 问题页：按现象查原因

常见问题页按现象组织：每条以员工看到的现象为标题（用页面原文或终端原文），下面写“原因”和“怎么办”。最后一条总是“以上都不是：联系管理员 hello@willfan.me，并附上需要提供的信息”。
