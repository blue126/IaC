# 页面模板

内容页按 Diátaxis 分四类。一页只用一种模板；写着写着需要另一类内容时，链接到对应页面。另有首页和分组页模板。

## 首页与分组页（`_index.md`）

目标：让读者在十秒内找到该看哪一页。不写正文知识。

```markdown
---
title: <标题>
description: <一句话：这里有什么>
weight: <分组顺序>
---

<一两句：按什么情况看哪一组。例如“第一次用，从「入门」开始；遇到具体问题，查「操作指南」和「常见问题」。”>
```

子页列表由 OINK 根据各页 `title` 和 `description` 自动生成，所以每页的 `description` 要写成一句完整的“这页解决什么问题”。

## 教程（Tutorial）

目标：带新员工完整做成一次，建立信心。只走一条成功路径，不讲分支和原理。

```markdown
# <做成什么>

做完这页，你将能够 <可观察的结果>。大约需要 <时间>。

开始之前，你需要：
- <前置条件>

## 1. <动作>
<一到三句。动作在前，结果在后。>
<成功标志：你会看到……>

## 2. ...

## 完成了
<如何确认成功>。下一步：[<相关操作指南>](/docs/guides/<slug>/)。
```

## 操作指南（How-to）

目标：已经会用的员工完成一个具体任务。假定读者知道自己要什么。

```markdown
# <如何做某事>

<一句话说明适用场景。>

1. <动作>
2. <动作>

做完后，<成功标志>。

如果 <常见失败现象>，见 [常见问题](/docs/reference/troubleshooting/#<锚点>)。
```

## 参考（Reference）

目标：查数值、规则、术语。按查找习惯组织，用表格，不写操作步骤。

```markdown
# <主题>

| 项目 | 值 | 说明 |
| --- | --- | --- |
| <名称> | <值> | <一句话> |
```

常见问题页按现象组织：每条以员工看到的现象为标题，下面写“原因”和“怎么办”，最后一条总是“以上都不是：联系管理员 hello@willfan.me，并附上 <需要提供的信息>”。

## 原理说明（Explanation）

目标：解释为什么这样设计，让员工理解规则背后的理由。不含步骤。

```markdown
# <主题>

<两三段说明设计和理由。可以配一张简图。>

## 这对你意味着什么
- <可感知的影响>
```
