# RemoteCC 用户文档

为 `cc.willfan.me/docs` 写面向员工的文档。读者会 Linux 基本操作，没有任何内部背景，通常是遇到问题才来看。每页只回答一类问题，读完能做成一件事或弄懂一件事。

站点源文件在 `remotecc/apply-site/docs/`。页面清单、分组和各页分工以该目录的 `ARCHITECTURE.md` 为准，本 skill 不重复。

加载本 skill 不代表授权修改 Worker、部署、提交或推送；这些边界按仓库 AGENTS.md 另行确认。

## 工作流程

1. **定位页面**：在 `remotecc/apply-site/docs/ARCHITECTURE.md` 找到目标页和它的职责。新增、合并或移动页面时，先改 `ARCHITECTURE.md`，说明它和现有页的分工。
2. **收集事实**：按下面的事实来源逐条核对，草稿里每条行为性事实（数值、时限、按钮名、命令、步骤顺序）都要能指回来源。来源冲突或查不到时停下来报告，不猜。
3. **按写法起草**：用[页面写法](references/page-templates.md)中对应的结构；术语与 `apply-site/design/text.json` 一致。
4. **安全检查**：逐条过下面的“绝不出现”清单。
5. **读者测试**：按[读者测试](references/reader-test.md)执行，修完发现的缺口再交付。
6. **交付**：页面写在 `ARCHITECTURE.md` 规定的路径；在 `remotecc/apply-site/docs` 运行 `hugo --gc`，除 LibSass 弃用警告外不得有其他 WARN 或 ERROR。写文档不改 Worker。给出改动文件、每条事实的来源清单、读者测试结果和未解决的问题。

## 事实来源（优先级从高到低）

1. `remotecc/apply-site/worker.js`：网站实际行为，包括路由、登录时效、下载规则、错误码。
2. `remotecc/apply-site/design/text.json`：员工在页面上看到的原文，按钮名、提示语和公开规格以此为准。
3. `remotecc/wsctl/docs/admin-handbook.md` 与 `wsctl` README：开户、续期、设备、流量额度的后台规则。只取员工可感知的结果，不搬运管理员操作。
4. 公开仓库 [workspace-onboarding](https://github.com/blue126/workspace-onboarding)：员工电脑上 AI 助手实际执行的接入步骤。
5. IaC `docs/guides/employee-*.md`：可能停留在旧流程，只作背景，事实必须回到 1–4 核实。

代码里查不到、只能由管理员确认的事实（例如网络路径），写进 `ARCHITECTURE.md` 并注明确认日期。

`remotecc/` 在主 checkout 中被 Git 忽略；在临时 worktree 里用 `git worktree list --porcelain` 定位主 checkout 读取，不复制。

## 绝不出现

- 任何凭据或其片段：私钥、令牌、密码、验证码样例以外的真实码、证书指纹真实值、SHA256 真实值。
- 员工个人数据：真实邮箱、姓名、员工 ID、主机名、分配的 IP。统一用示例值：员工 ID `alice`、主机名 `alice-vm`、邮箱 `you@example.com`，前面写“例如”标明是示例。
- 管理员侧细节：执行器、Semaphore、BWS、`wsctl`、Portal、`/admin/*` 路由、内网管理地址、Terraform/Ansible。员工需要知道的只是“联系管理员”。
- 让员工在本机浏览器打开 Claude 授权链接、在本机登录个人 Claude 账号，或绕过 VPN 的做法。
- 未上线的功能和已撤回的方案。
- 对带宽、速度或可用性的承诺（例如“不限速”）。

以上规则同样适用于截图、终端输出、日志、HTML 注释和附件。配图只用示例账号的页面和终端截取，不截真实员工的「我的工作区」；接入时得到的桌面地址和证书指纹只说“以接入时给出的为准”，不写具体值。

## 写作规则

- 中文，第二人称“你”，短句。一个步骤只做一个动作，动作在前、结果在后。
- 每句话必须是动作、成功标志或会出错处的提醒。删掉复述、安抚和原理解释（“VPN 只接管……”“系统为 macOS、Linux 或 Windows”“以「我的工作区」显示为准”这类）；示例值前写“例如”即可。
- 用词固定：「你本地」（不说“本机”）、「你本地的终端」、「VM」（第一次出现时说明“你的工作区是一台专属的 Linux 虚拟机，下称 VM”）、「VM 终端」、「远程桌面」。「工作区」只用于产品名和「我的工作区」。说“终端”时写清是哪一台机器的，必要时分系统说明它指什么。
- 本站界面（`text.json`）用原文并加引号，例如点击「下载设备接入包」。第三方或远端界面（Claude 登录页、Anthropic 邮件、终端提示、浏览器提示）不保证原文：描述动作和结果（“选择用 Google 或 Apple 登录”“终端提示登录成功”），只有用户或截图确认过的才写原文（例如邮件里黑色的「Sign In」按钮）。
- 命令放代码块，个人值用上面的示例值，不用 `<...>` 占位符（复制进 shell 会被当成重定向）；同时给出预期输出或成功标志。
- 站内链接写目标页的完整路径并以斜杠结尾（路径见 `ARCHITECTURE.md`）。
- 警告只放在会出错的那一步前面，不集中堆在开头。
- 同一件事只在一页讲完，其他页链接过去。数值和时限只写在 `ARCHITECTURE.md` 指定的那一页。

## 核实流程，不靠推断

- 从员工视角把真实流程走一遍：每一步他看到什么、下一步从哪里拿到信息（例如桌面地址来自 `workspace-login` 的输出，不是回头找 AI 助手）。
- 列出所有分支再动笔：登录方式（Google / Apple / 邮箱 magic link）、操作系统、“如果出现授权码”这类条件步骤要写“如果”。
- 跨设备的操作写清怎么做：例如邮件在你本地收、链接要在远程桌面打开，就写出复制、粘贴的具体方法和粘贴不了时的后备入口。
- 界面细节只写来源里确认过的。查不到就问用户，不从旧记录或其他环境（别的浏览器、别的桌面后端）推广。
- 用户纠正过的事实立刻记入 `ARCHITECTURE.md` 的“管理员确认的事实”，之后不再改回或换个说法重新引入；只改用户指出的地方，不顺手加没要求的内容。
- 安全检查交给能自动完成的一方（例如证书 pin 由 AI 助手的 verify 核对），不要求员工手工比对指纹。

## 页面格式（OINK）

- 步骤用 Markdown `1.` 编号；样式会把节内步骤渲染成 a/b/c、下一层渲染成 i/ii/iii，与 `## 1.` 这类节编号区分。
- 提示框（`> [!CAUTION]`、`> [!WARNING]`）和可复制的代码块一律顶格，不缩进进列表；放在列表中间时空一行断开，后面的编号会自动续上。列表最后的结论或可选步骤也写成列表项，不在列表后面另起顶格段落。
- 命令用 `console` 代码块加 `$` 提示符和标题，标题写在哪台机器运行，例如 ```` ```console {title="VM 终端"} ````；复制按钮只复制命令。交给 AI 助手的话用 ```` ```text {title="复制给 AI 助手" wrap=true} ````。
- 只有一节的页面不要再写与标题重复的小节名；外链、站内链接保持可辨认的链接样式。
- 交付前截图检查：缩进、编号、提示框位置、代码块和链接样式，确认没有重复标题。
